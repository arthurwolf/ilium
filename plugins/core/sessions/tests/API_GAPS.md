# API gaps of the Sessions feature tests

Every gap-dependent testkit item is used only in `tests/features/common.rs` ("gap helpers"), so a missing item breaks that file alone.

- `ilium-plugin-testkit`: `FakeHost::agent(&mut self) -> &mut FakeAgent` with `add_signature(&mut self, spec: ilium_plugin_sdk::primitives::SignatureSpec)` and `set_session(&mut self, pane: u64, session: ilium_plugin_sdk::primitives::SessionRef)`; a pane without `set_session` has no verified session (F-076, page sample "Resume verified agent sessions": `agent::session(pane)` is `None` until the id is verified).
- `ilium-plugin-testkit`: `FakeHost::active_timers(&self) -> Vec<(u32, Option<u32>)>` listing the timers the plugin set and did not cancel, as (first delay ms, repeat ms), oldest first (F-076, sample "Detach and reattach", `timers::set` and `timers::cancel`).
- `ilium-plugin-testkit` (dependencies): `proptest = "1"` and `serde_json = "1.0.151"` are already dev-dependencies of the crate; nothing missing there.
- Documentation (trigger of the restore flow): no page names the event that tells the plugin which panes were restored. The tests assume `Event::PaneCreated(PaneInfo { is_restored: true, .. })` for each restored pane (the `is_restored` field exists in the WIT type) and `PaneLifecycleChanged` with `PaneLifecycleState::Running` for the thaw (named on the page).
- Documentation (trigger of the graceful stop): the page does not say when `terminate-pane-process` is submitted nor which panes "the recovery policy does not relaunch" are. The tests assume `deactivate(DeactivationReason::Shutdown)` of the server side and that plain shell panes are such panes.
- Documentation (create-project): the page gives no trigger for `create-project` (command, CLI or service method), so no behaviour test of it exists. Request needed: name the trigger and the dedup key `project-<root>` contract in the "Sessions per project" sample.
- Documentation (service and topic): the `ilium.core.sessions/snapshots` service (methods list, save, restore) has no payload or reply shapes and the `saved` topic is only `{ session, bytes }`; no behaviour test is possible beyond the page text.
- Documentation (snapshot sections): the sample "snapshot-sections" and the migration page define the messages `snapshot-section` and `restore-section` but the Sessions page never states how the plugin offers sections to the kernel writer, so only page statements are tested here.
- Documentation (render): the page shows the restore summary figure but names no view or panel id for it (only the activation `view:sessions.list`), so no golden render test at widths 40/80/120 can be written. The figure is 50 cells wide while its caption says 48 columns (test `doc_076_restore_summary_figure_fits_the_stated_48_columns` is expected to fail until the page is fixed).
- Documentation (consistency): the page and the core-plugins index say "server side only" while the manifest has a `client` side (needed for `settings.write-kernel:session`); `reference-kernel-and-boot.md` says Sessions is disableable while `core-plugins.md` (LIF-276) lists it as essential and not disableable.
- Skeleton: `SessionsServer` and `SessionsClient` export nothing (`exports = []`) and the manifest has no `contributes` block for the extension points, the service, the topic and the `session` settings tab, although the page lists them.
- Part ports (tests/port/common.rs, same gaps as part features): `ilium-plugin-testkit` `FakeHost::agent()` with `add_signature` and `set_session` (F-076); the twins assume restored panes arrive as `Event::PaneCreated` with `is_restored: true` and thaw on `PaneLifecycleChanged` `Running` (F-075, F-076). Kernel-side recovery records (`AgentRecovery`, wire frames, process evidence) have no plugin API; the twins assert the plugin-visible consequence (resume only for a verified session, exact session id, no replayed input).
