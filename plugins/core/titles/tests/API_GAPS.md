# API gaps of the titles feature tests

- `ilium-plugin-core-titles`: `pub struct TitlesClient` with `impl Default`, `Lifecycle`, `Handler` and `Views` (client side, grant `ui.panels`, panel id `titles.preview`), plus `ilium_plugin_sdk::testing::FakeHost::activate::<TitlesClient>()` working on `side("client")` (F-043, preview_render.rs). The skeleton declares only `TitlesServer`, and `manifest.json` (exact, COR-050) has no `client` entry.
- `ilium-plugin-testkit`: `impl FakeHost { pub fn inference_requests(&self) -> Vec<(RequestId, ilium_plugin_sdk::host::inference::CompletionRequest)> }` (every `inference.complete` call the plugin made, in order). Needed by all behaviour tests of F-041, F-043, F-044, F-045 (api-inference.md): the harness has no way to read the requests a plugin sent to the model.
- `ilium-plugin-testkit`: `impl FakeHost { pub fn complete_inference(&mut self, request: RequestId, completion: ilium_plugin_sdk::host::inference::Completion) }` stores the completion for `take_completion` and queues `request-completed` with `Outcome::Ok` for the next `deliver`/`settle` (F-041, api-inference.md "A call returns a request id at once"). `complete(RequestRef, Outcome)` cannot carry the completion text.
- `ilium-plugin-testkit`: `FakeHost::inject_failure("inference.complete", PluginError)` must accept the import name `inference.complete` and the code `not-found` (DEV-493; api-inference.md "If no provider is selected, the call fails at once with not-found"). Used by `f_041_a_failed_inference_call_*`.
- `ilium-plugin-testkit`: `impl FakeHost { pub fn script_hook_reply(&mut self, point: &str, reply: ilium_plugin_sdk::exports::HookReply) }` (a contributor answer for the next chain run of a point the plugin owns) and `pub fn hook_calls(&self) -> Vec<ilium_plugin_sdk::exports::HookCall>` (the chains the plugin started, with `payload_json`). Needed by the `before-apply-title` tests (F-041, api-extension-points.md "transform").
- `ilium-plugin-testkit`: `impl FakeHost { pub fn published_topics(&self) -> Vec<(String, String)> }` (topic name, payload JSON, in publish order). Needed by the `title-applied` topic tests (F-041), same item as in the layout feature gaps.
- `ilium-plugin-testkit`: `FakeHost::settings().set(key, value)` must accept the kernel keys used here: trigger keys named by the event names of the Triggers tab (`"Agent receives a prompt"`, `"Agent finishes work"`) with a JSON array of action names (`"Retitle element"`, `"Restructure project"`, `"Restructure all projects"`), `inference.instructions.<name>` for the six instruction inputs, and `restructure_prompt_token_limit` (rejects 0). It must reject an unknown action name (F-044, F-045, F-043).
- `ilium-plugin-testkit`: `FakeHost::restart_with(Vec::new())` is used as "restart the instance with the same code" for the undo-token test; if a different call is intended, expose `restart(&mut self)` (F-043, page sample 3: the token does not survive a restart).

## Assumptions the manual leaves open (tests pin them, the implementation or the manual must confirm)

- The server sends the preview to the client as a `Message` event on channel `titles.preview` with the JSON payload `{"old_outline": [..], "new_outline": [..], "moves": n, "groups": n}`; the page says only "The server sends the two outlines to the client" (page sample 4).
- Inference purposes: `pane-title` for titles (page sample 1); a purpose containing `restructure` for tree organisation (not named on the page).
- The model's restructure reply uses the JSON plan of the existing implementation (`ilium-client/src/restructure.rs`: `children` with `kind` pane/folder/group/existing_group/split_view, plus `animations`); three attempts in all, then the automatic retry delay of 60 s doubling to at most 30 min (`automatic_restructure_retry_delay`).
- The undo command id is `ilium.core.titles/undo-organise` (page sample 3, whose manifest sample contributes `undo-organise`). The complete manifest has no `contributes`, so no command row is asserted on the manifest.
- The settings figure of the page shows labels (`Short phrase`, `Name panes from prompts`) that differ from the user documentation (Labeling/Summarization). It is marked illustrative, so only its text is pinned as a golden file, not rendered output.
