# API gaps of the text-triggers feature tests

Items the tests call that the skeleton lacks, or manual details the tests had to assume.

- ilium-plugin-testkit: `FakeHost::output_filters(&self) -> Vec<(u64, ilium_plugin_sdk::primitives::OutputFilter)>` returns every output filter the plugin installed through `add-output-filter`, as (pane, filter). Requirement F-056 (page "Match output and answer"): the filter set is the observable channel of "each rule becomes one output filter on every agent pane".
- ilium-plugin-testkit: `FakeHost::set_hook_contributor(&mut self, point: &str, reply: HookReply)` registers a stub contributor of an extension point the plugin provides (here `before-fire`); the plugin must apply the reply (`refuse` stops the send, `pass` continues, a mode-forbidden reply counts as pass). F-056 (page "Extension points").
- ilium-plugin-testkit: `FakeHost::hook_calls(&self, point: &str) -> Vec<HookCall>` returns the hook calls the plugin made to the contributors of `point`. F-056 (payload: rule, pane, match, reply_length).
- ilium-plugin-testkit: `FakeHost::contribute_collect(&mut self, point: &str, entry_json: &str)` adds an entry to a collect point the plugin provides (here `rule-packs`). F-056. Assumption: the filter id of rule `i` of pack `p` is `<p>-<i>`; the manual does not state it.
- ilium-plugin-testkit: `FakeHost::published_topics(&self, topic: &str) -> Vec<String>` returns the JSON payloads the plugin published on a topic (here `ilium.core.text-triggers/fired`, payload `{ "rule", "pane" }`). F-056.
- ilium-plugin-testkit: `FakeHost::config_table(&self, table: &str) -> Option<serde_json::Value>` reads a table of the fake `config.toml`; `FakeHost::seed_config_table(&mut self, table: &str, value: serde_json::Value)` writes one (with unknown keys). COR-033, COR-011 ("keep unknown keys", same tables).
- ilium-plugin-testkit: `FakeHost::seed_settings_unchecked(&mut self, key: &str, value: serde_json::Value)` writes a setting without the row validation, as a hand edit of `config.toml` does; needed to render the invalid-pattern notice that the host would refuse to write. F-056 (page second figure).
- Manual gap (assumption in the tests): the page declares the list rows `patterns` and `replies` but not where rule names (`names`, the group titles "Confirm prompts") and enabled flags (`enabled`, list of bool in rule order) live; the tests use those two keys. The settings page view target is assumed to be `ViewTarget::SettingsPage("text-triggers")`, the filter id of rule `i` is `rule-<i>` (the page's toggle key), the rate is 2 per second, the session count key is `count/<filter id>` (little endian u64) and the `warn` level name is lower case.
- Manual gap: the page lists the service `ilium.core.text-triggers/test-rule` but its request and reply shapes are not stated, and `reference-test-harness.md` lists no service for this core stub; the tests only check the page text for it.
- Manual defect found by tests: the page's Extension points table marks `rule-packs` risk as `standard`, while `reference-extension-security.md` (SEC-293 corrected table) says `high`; the test `doc_293_rule_packs_is_high_risk_in_the_corrected_table_and_so_on_the_page` fails until the page is corrected.

## Ports part (tests/port)

- ilium-plugin-testkit: `FakeHost::call_service(&mut self, service: &str, request_json: &str) -> Result<String, ilium_plugin_sdk::types::PluginError>` calls a service the plugin provides (here `ilium.core.text-triggers/test-rule`). Requirement PORT:ilium-client/src/text_trigger_dialog/preview_tests.rs (all eight twins). Why: the dialog preview is only reachable through this service.
- Manual gap: `test-rule` request `{pattern, reply, sample}` and reply `{preview, issues}` are assumed; preview lines are `✓ a[bb]a` (match, bracketed), `· xxx` (no match), `✓ alpha  ⟪zero-width match⟫`, the loop warning `⚠ Reply also matches this regexp; echoed input can loop.`; issue `capture-limit` for a 1 MiB sample cut inside a scalar. Requirement PORT:ilium-client/src/text_trigger_dialog/preview_tests.rs.
- Manual gap: settings keys `delays` (list of integer seconds, default 60, 0..=86400, 0 sends immediately), `targets` (`agents`, `terminals`, `both`, default both) and `ids` (authored stable ids: non-blank, no control characters, unique) are assumed. Requirement PORT:ilium-ipc/src/text_trigger.rs (all six twins) and PORT:ilium-server/src/text_triggers.rs.
- Manual gap: a rule's reply is sent only after `delays[i]` seconds of host clock (`advance_clock`); the host dedup window is 10 minutes, so "fires again" twins use a clock gap above it. Requirement PORT:ilium-server/tests/text_triggers.rs::the_reply_waits_for_the_rules_delay_after_detection.
- Manual gap: tab row keys `delay-<i>` (Changed with Number or Text, blank means 60, clamped to 0..=86400) and `target-<i>` (Selected with Index 0 agents, 1 terminals, 2 both). Requirement PORT:ilium-client/src/text_trigger_dialog.rs.
- Manual gap: the trigger event actions tab (originals trigger_settings*.rs) is assumed to be `ViewTarget::SettingsPage("trigger-events")` over config table `[triggers]` with list settings `startup_complete`, `agent_waiting_background`, `agent_approval_required`, `agent_prompt_submitted`, `agent_finished_work` holding `retitle_element`, `restructure_project`, `restructure_all_projects`; toggle action keys are `<event>/<action>` and `<event>/none`; defaults as in the monolith. Requirement PORT:ilium-client/src/trigger_settings.rs and trigger_settings_ui.rs.
- Manual gap: an invalid source in the `[text_triggers]` table (not a table, missing patterns, non-list, bad regexp, empty pattern, multiline reply, duplicate ids, over 512 KiB) keeps the last valid rules and is not rewritten; an identical rewrite changes nothing. Requirement PORT:ilium-server/src/text_trigger_config.rs.
- ilium-plugin-testkit: `FakeHost::tree()` returns a handle with `add(TreeNode) -> u64` (used by the existing features tests); the ports additionally add a plain terminal pane with `agent: None`.
