# API gaps of the Ambient look feature tests

Every gap-dependent testkit item is used only in `tests/features/common.rs` (and, for the extension helpers, at the end of `tests/features/extension_points.rs`), so a missing item breaks those files alone.

- `ilium-plugin-testkit`: `FakeHost::last_tree(&mut self, target: ViewTarget) -> UiTree`. The tree the plugin returned for the last `host.render(target, ..)`, to assert the gallery thumbnail and clip names (F-103, F-093; page sample 3 and 4).
- `ilium-plugin-testkit`: `FakeHost::storage_mut(&mut self) -> &mut FakeStorage` with `FakeStorage::put(&mut self, bucket: Bucket, key: &str, value: &[u8])`. Seeds the `last_suggestion` value of global storage before activation (F-103; page sample 4).
- `ilium-plugin-testkit`: `FakeHost::kernel_settings(&mut self) -> &mut FakeKernelSettings` with `set_tab(&mut self, tab: &str, values: serde_json::Value)` and `written(&self) -> Vec<(String, String, String)>` (tab, key, JSON text). For the `animations` kernel tab (COR-030, COR-033).
- `ilium-plugin-testkit`: `FakeHost::published_topics(&self) -> Vec<(String, String)>` (topic, payload JSON), for `ilium.core.ambient/look-changed` (F-093).
- `ilium-plugin-testkit`: `FakeHost::extensions(&mut self) -> &mut FakeExtensions` with `collect(&mut self, point: &str) -> Vec<serde_json::Value>` (entries, highest priority first) and `contribute(&mut self, point: &str, id: &str, priority: i64, entry: serde_json::Value)` (F-093, F-094; reference-test-harness.md core stub table).
- `ilium-plugin-testkit`: `FakeHost::call_service(&mut self, service: &str, method: &str, payload_json: &str) -> serde_json::Value`. Calls a plugin service through its `service-provider` export and returns the parsed JSON of the reply (F-093, service `ilium.core.ambient/look`).
- Skeleton `plugins/core/ambient/src/lib.rs`: `AmbientClient` implements no `ServiceProvider` and no `HookHandler`, and exports only `views`. The page offers the service `ilium.core.ambient/look`, so the client exports must also list `service-provider` (F-093).
- Skeleton `plugins/core/ambient/manifest.json`: the page text says the plugin owns `palettes` and `style-presets` (grants `extensions.provide:ilium.core.ambient/<point>`), offers the service `ilium.core.ambient/look` (grant `services.provide:`) and publishes the topic `ilium.core.ambient/look-changed`, but the Complete manifest block (identical to the file) lists none of them. Tests `manifest_093_provides_*` and `manifest_093_declares_*` fail until the page block and the file both gain them (F-093, F-094).
- Documentation: the `scene-preview` view of the `preview` row is not an id in `contributes.panels` (only `gallery` is), although reference-settings-rows.md row 14 says the view must be an own `panels` id. Test `manifest_093_preview_view_names_a_panel_the_plugin_contributes`.
- Documentation: the `observer` row sets `allow_current: true`, which reference-settings-rows.md row 13 says needs `location.observer` on the client side, but the grant list lacks it. Test `manifest_093_allow_current_needs_the_location_observer_grant`.
- Documentation: reference-test-harness.md lists the service of the `ilium.core.ambient` stub as `none` while the page offers `look`. Test `doc_f_093_harness_core_stub_row_offers_the_look_service_the_page_declares`.
- Documentation: the page names no panel id for the location picker (sample 2 ignores the view argument) nor the mapping from the selected or suggested scene to the gallery files; the tests assume `thumbs/<scene>.png`, `clips/<scene>.webm` for the scene of the `scene` row, or the stored `last_suggestion` after `semantic` turns on, and look for the picker in the panels `location`, `scene-preview`, `gallery`.
- Documentation: the page does not say where the surface frames of the preview are written from (`show_frame` of sample 1 is a free method of the sample panel type), so `write_surface` calls are not asserted.
- Documentation: the shared look, dither and display rows (colour mode, palette, dither, frame-rate cap) are not in the manifest, so their behaviour is only pinned through the user document (`docs_user.rs`).
- Part ports (tests/port/): the pure modules `control`, `number`, `values`, `rows`, `hover`, `semantic`, `visibility`, `credit`, `panel` and `help` hold the moved rules and are twinned at the data boundary on the synthetic registry of `tests/port/panel_fixture.rs`. The kernel tests that drive the whole Settings screen through `App` and a `TestBackend` (drawing, key and mouse routing, project config persistence, preview painting, plugin editor frame) have no plugin-API surface and stay in the kernel (KERNEL-STAYS). G2: settings rows are read-only, so the Animations tab stays kernel. G9: no scene side glue, so the scene registry is passed in as `RowInputs`. The set-setting service still lives on the server side of the skeleton; the plan moves it to the client with `HostKernelSettings::write("animations", ..)` and inverts COR-030, which needs a coordinated manifest, manual and spec-test change that was not made here (PORT:* rows, F-093, F-094).
- `ilium-plugin-testkit`: `NativeBridge` (`src/host/bridge_defaults.rs`) answers `HostKernelSettings::write` and `read` with `unsupported` ("the fake host does not model this call"). Wanted: route `write(tab, key, value_json)` into `FakeKernelSettings::set`, refuse a tab whose `settings.write-kernel:<tab>` grant the side lacks with `not-permitted`, and answer `read(tab)` from `FakeKernelSettings::tab`. Needed by `tests/features/set_setting.rs::cor_030_a_valid_value_reaches_the_kernel_write`, which then asserts the exact write unconditionally.
- Kernel (G2/20.5): a plugin write to the `animations` kernel tab lands in `config.toml` table `[animations]` (`ilium-plugin-host/src/config_settings.rs` `KERNEL_TABS`), but the client reads `AnimationSettings` from the project config (`ilium-client/src/project_config.rs`, `background_animation/mod.rs`) and never reloads after a plugin write. Wanted: `ilium-client` consumes `Event`/topic `ilium.kernel/settings-changed` for tab `animations` and applies the keys `scene` (to `AnimationSettings::kind`), `semantic` (to `semantic_scope`), `observer` and `saved_places`. Until then `set-setting` stores values nobody applies. Needed by the gallery Enter action and the whole Animations tab.
- Kernel (G2): `ilium-client/src/settings_ui.rs` draws only the built-in `SettingsTab` list; a contributed `kind: "tab"` row set is shown read-only in the Plugins list, and `plugin_host/settings_rows.rs` edits only `toggle`, `number` and `choice` rows. Wanted: a plugin-owned tab that replaces a kernel tab id when its plugin is enabled (`SettingsTab::Animations` drawn by `animation_settings_ui.rs`, 4989 lines), with editable `preview`, `location` and `map` row types. Blocks the move of `animation_settings_ui.rs`, `animation_rows.rs`, `animation_hover.rs`, `value_animation.rs`, `value_scene.rs`, `animation_visibility.rs` (drawn by the Animations tab) and `introduction.rs` (`AnimationKind::introduction()` called by the tab).
- Kernel: `semantic_animation.rs`, `app_semantic_animation.rs`, `restructure.rs` and `restructure_recommendations.rs` call the semantic catalogue and validation synchronously from the client tick and the restructure flow. Wanted: a synchronous plugin call from client code (`App::call_plugin_service_blocking(service, method, payload) -> Result<String, PluginError>` with a time bound), or an intent that applies animation parameters (`Intent::SetAnimationParameters { speed_percent, density_percent, scene }`) so the plugin decides asynchronously from `panes` status events.
- Kernel: `animation_visibility.rs` reads the drawn `ratatui::buffer::Buffer` once per second per frame and `background_acceptance.rs` is a test-only module over the real UI; neither has a plugin-API surface. They stay kernel.

## Verified against the tree on 2026-11-14 (visuals group, consumer pass)

- Kernel (A2): a `kernel-settings` write to tab `animations` lands in `config.toml` table `[animations]` (`ilium-plugin-host/src/config_settings.rs:40`), and no code in `ilium-client`, `ilium-server` or `ilium` reads that table: the client's `AnimationSettings` come from the project configuration (`ilium-client/src/project_config.rs:40`, written by `set_animation`, :125). `settings-changed` (`ilium-client/src/plugin_host/host.rs:1906`) only informs the plugin that changed its own row. Wanted: a client consumer that applies a write to tab `animations` (keys `scene`, `semantic`, `semantic_scope`, `observer`, `saved_places`) to the live project configuration, or a tab-to-table mapping that targets the project configuration. Until then the `set-setting` service and any gallery Enter action store values that nothing applies, so the gallery is not wired to it.
- Kernel (A3): no animation-parameter intent exists in `Intent` (`ilium-plugin-api/src/generated/types.rs`, lines 4721 to 4762) and `ilium-client/src/plugin_host/commands.rs:19` `invoke_plugin_command` returns no reply, so `semantic_animation.rs` and `app_semantic_animation.rs` cannot call the plugin. Wanted: `App::call_plugin_service_blocking(service, method, payload_json, deadline) -> Result<String, PluginError>` or `Intent::SetAnimationParameters { scene, speed_percent, density_percent }`.
- Kernel (A5): nothing collects the `palettes` and `style-presets` extension points; `ilium-ambient/src/style.rs` and `style_filters.rs` use their built-in tables only.
- Package (A6): `plugins/core/ambient/assets/` does not exist, so the gallery cannot reference `thumbs/<scene>.png` and `clips/<scene>.webm` yet.
- Cuts: `docs/tasks/02-cuts/ambient.md` holds no hunks and keys A1 to A7 name the missing consumer for each blocked kernel file.

## Update (visuals group, move pass)

- Kernel (A2) is closed for the keys `scene` and `semantic`: `ilium-client` applies a change of the `[animations]` table to the live animation (`plugin_host/animation_table.rs`, `App::apply_plugin_animation_table`), and the client part forwards a user change of its rows to `set-setting` (`src/forward.rs`, `tests/features/forward.rs`). Still wanted: the same for `observer` (the client keeps the observer location in the animation home's `.ilium/config.yaml`) and `saved_places` (the kernel has none), and a write-back of the current scene into `[animations]` when the kernel Animations tab changes it, so a read of tab `animations` shows the live value.
- `ilium-plugin-testkit`: `FakeHost::stub_service` and `service_calls` are what `tests/features/forward.rs` uses. The fake answers any unstubbed service with `{"ok":true}`, so the test pins the call and the refusal handling, not the server part's write; that write stays pinned by `tests/features/set_setting.rs`.
