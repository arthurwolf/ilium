# API gaps found by the kanban features tests

- ilium-plugin-testkit: `impl FakeHost { pub fn published_topics(&self) -> Vec<(String, String)> }` (topic `ilium.core.kanban/card-moved`, F-024): `(topic, payload_json)` of every topic publication the plugin made, in order. Not yet used by a test; needed to assert the `{ board, card, to_column }` payload after a card move.
- ilium-plugin-testkit: a way to invoke an extension point the plugin owns with contributors (`card-actions` collect, `card-moved` observe), for example `FakeSession::call_extension(point: &str, payload_json: &str) -> Result<Vec<String>, HarnessError>` (F-024); the tests only read the page tables and the core stub until it exists.
- ilium-plugin-api / manual: how a `board` pane is bound to its board file is not specified. The tests assume the page sample constant: every board pane in `board_host` is backed by `project:docs/plan.md` after `PaneCreated` with content kind `ilium.core.kanban.board` (F-024). The manual must state where the storage path lives (pane metadata shape, `persist: "metadata"`).
- ilium-plugin-api / manual: the manifest of the page has no `contributes.commands`, menu items, `extensions.provide:*`, `services.offer` or `topics` grants although the page text lists points, service and topic; the page says the manifest is exact, so the contribution ids for "Create board from Markdown" and the dialog popup are unspecified. The tests assume command id `ilium.core.kanban.create-board-from-markdown` and popup view id `open-board` (F-025).
- ilium-plugin-api / manual: the drag keys of the board are unspecified. The tests assume `card-<column>-<row>` for a card source and `column-<column>` for a column target in `ui-action` events (F-024).
- ilium-plugin-api / manual: the exact `ui-action` keys and task ids of the card check lists (`card-<card id>`, item id) are not defined (card id format), so the check-list `ui-action` path of the page sample is only tested through the checkbox click (F-024).
- ilium-plugin-testkit: the import name for the conditional atomic write used by `FakeHost::inject_failure` is not listed; the tests assume `"fs.write-atomic"` (page sample "Read and write the Markdown file safely"; F-024).
- ilium-plugin-testkit: `Screen::find` and `FakeHost::click` use `(row, column)` and `(column, row)` respectively; the tests follow the signatures in `host.rs`.
- manual defect: the manifest activation trigger `pane-kind:kanban` does not name the declared pane kind `board` (global id `ilium.core.kanban.board`), while [PKG-060] requires a trigger that names an own contribution to name a declared one. The tests follow COR-050 (manifest exact) and do not assert PKG-060 for this plugin.
- manual / implementation mismatch: the manifest settings rows are `card_preview` (toggle, default true) and `column_width` (12..60, default 24) while the current implementation and the user docs store `card_preview_lines` (default 4, range 1..10) and `minimum_column_width` (default 45, range 10..80) in `[kanban_board]`. The tests assert the manifest rows and the user-doc keys separately; the manual must say how the two relate (F-024, COR-033).
- ilium-plugin-testkit: `FakeSettings::set` for a key outside the plugin tab (the kernel `[kanban_board]` keys) and the error code of a refused value are specified only by SET-020 ("refused with the row note"); the tests assume `ErrorCode::InvalidArgument` as in the tree suite.
- ilium-plugin-testkit: folder-column boards (`board/To do/001-write-the-migration.md`, limits 8192 entries and 1 MiB) need a fake directory listing for `fs.list` and a way to bind a pane to a directory; not tested beyond the documented rules (F-024).
- ilium-plugin-testkit: creating, renaming and deleting cards and columns (keys `n`, `c`, `e`, `d`) needs text entry into the plugin's dialogs (view ids and field keys unspecified); only the confirmation refusal of `d` is tested (F-024).
- ilium-plugin-testkit (ports): `FakeFs::read(path) -> Option<Vec<u8>>` and `FakeFs::write(path, &[u8])` are assumed to accept the shorthand `scope:path` for folder-column files (`project:board/To do/notes.txt`); the port twins in tests/port/ use it (F-024, PORT:ilium-client/src/board.rs::folder_save_preserves_non_markdown_files_in_column).
- ilium-plugin-testkit (ports): `FakeHost::inject_failure("fs.write-atomic", Conflict)` is consumed by the next write attempt; the twins for the revision-conflict originals assume one injection per refused attempt (3 attempts), as in the features suite.
