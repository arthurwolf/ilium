# API gaps found by the kanban features tests

- ilium-plugin-testkit: `impl FakeHost { pub fn published_topics(&self) -> Vec<(String, String)> }` (topic `ilium.core.kanban/card-moved`, F-024): `(topic, payload_json)` of every topic publication the plugin made, in order. Not yet used by a test; needed to assert the `{ board, card, to_column }` payload after a card move.
- ilium-plugin-testkit: a way to invoke an extension point the plugin owns with contributors (`card-actions` collect, `card-moved` observe), for example `FakeSession::call_extension(point: &str, payload_json: &str) -> Result<Vec<String>, HarnessError>` (F-024); the tests only read the page tables and the core stub until it exists.
- ilium-plugin-api / manual: how a `board` pane is bound to its board file is not specified. The tests assume the page sample constant: every board pane in `board_host` is backed by `project:docs/plan.md` after `PaneCreated` with content kind `ilium.core.kanban.board` (F-024). The manual must state where the storage path lives (pane metadata shape, `persist: "metadata"`).
- ilium-plugin-api / manual: the manifest of the page has no `contributes.commands`, menu items, `extensions.provide:*`, `services.offer` or `topics` grants although the page text lists points, service and topic; the page says the manifest is exact, so the contribution ids for "Create board from Markdown" and the dialog popup are unspecified. The tests assume command id `ilium.core.kanban.create-board-from-markdown` and popup view id `open-board` (F-025).
- ilium-plugin-api / manual: the drag keys of the board are unspecified. The tests assume `card-<column>-<row>` for a card source and `column-<column>` for a column target in `ui-action` events (F-024).
- ilium-plugin-api / manual: the exact `ui-action` keys and task ids of the card check lists (`card-<card id>`, item id) are not defined (card id format), so the check-list `ui-action` path of the page sample is only tested through the checkbox click (F-024).
- ilium-plugin-testkit: the import name for the conditional atomic write used by `FakeHost::inject_failure` is not listed; the tests assume `"fs.write-atomic"` (page sample "Read and write the Markdown file safely"; F-024).
- ilium-plugin-testkit: `Screen::find` and `FakeHost::click` use `(row, column)` and `(column, row)` respectively; the tests follow the signatures in `host.rs`.
- manual / implementation mismatch: the manifest settings rows are `card_preview` (toggle, default true) and `column_width` (12..60, default 24) while the current implementation and the user docs store `card_preview_lines` (default 4, range 1..10) and `minimum_column_width` (default 45, range 10..80) in `[kanban_board]`. The tests assert the manifest rows and the user-doc keys separately; the manual must say how the two relate (F-024, COR-033).
- ilium-plugin-testkit: `FakeSettings::set` for a key outside the plugin tab (the kernel `[kanban_board]` keys) and the error code of a refused value are specified only by SET-020 ("refused with the row note"); the tests assume `ErrorCode::InvalidArgument` as in the tree suite.
- ilium-plugin-testkit: folder-column boards (`board/To do/001-write-the-migration.md`, limits 8192 entries and 1 MiB) need a fake directory listing for `fs.list` and a way to bind a pane to a directory; not tested beyond the documented rules (F-024).
- ilium-plugin-testkit: creating, renaming and deleting cards and columns (keys `n`, `c`, `e`, `d`) needs text entry into the plugin's dialogs (view ids and field keys unspecified); only the confirmation refusal of `d` is tested (F-024).
- ilium-plugin-testkit (ports): `FakeFs::read(path) -> Option<Vec<u8>>` and `FakeFs::write(path, &[u8])` are assumed to accept the shorthand `scope:path` for folder-column files (`project:board/To do/notes.txt`); the port twins in tests/port/ use it (F-024, PORT:ilium-client/src/board.rs::folder_save_preserves_non_markdown_files_in_column).
- ilium-plugin-testkit (ports): `FakeHost::inject_failure("fs.write-atomic", Conflict)` is consumed by the next write attempt; the twins for the revision-conflict originals assume one injection per refused attempt (3 attempts), as in the features suite.

## Move blockers (verified 2026-11-14)

The `kanban` kernel files stay PORT-KEEP after the gap streams. The list below is the exact reason per file; the cuts file `docs/tasks/02-cuts/kanban.md` carries the key table.

- `ilium-client/src/board.rs`, `board_ui.rs`: the board is a kernel pane kind (K2).
- `ilium-client/src/filesystem/{boards,board_app}.rs`: markdown reads and writes of the board pane; `fs` is available to a plugin, but the pane that calls it stays in the kernel (K2).
- `ilium-control/src/documents.rs`: called by the control executor (`ilium-client/src/control/executor.rs`), K4.
- Settings rows: the manifest still has `card_preview` and `column_width` (12 to 60), while the built-in keys are `kanban_board.card_preview_lines` (1 to 10, default 4) and `minimum_column_width` (10 to 80, default 45). The plan says the built-in names win. Changing them touches `tests/features/settings.rs` and the manual block (K9) and the kernel keys stay read by `ilium-client/src/config.rs` (K8).
- Service `set-setting`: the manifest provides it on the server side with `{tab, key, value}`; the plan asks for a client-side provider with `{key, value}` that writes `kernel-settings` `set("kanban-board.<key>")`. Changing sides changes grants, exports and `tests/features/service.rs` (K9).

Blocker keys (verified against the tree on 2026-11-14; each names the exact missing piece):

- K1 intents. `ilium-server/src/plugin_host/facade.rs` `apply_intent` routes only RenameNode, MoveNode, CloseNode, SetNodeLocked, CreatePane, ResizePane, CreateGroup, CreateSplit, SetBookmarked, SetExpanded, Message, SetStatusSegment, ClearStatusSegment, SetDecoration, ClearDecoration, SignalPane, OpenView and CloseView. Every other arm ends in `unsupported("this intent")`: `Intent::SendInput` (needs `Delivery::{Typed, Submitted, Pasted}` plus `stages` / `prompt_epoch` mapped to the server requests `UserKeyInput`, `SubmitTerminalText`, `PasteTerminalText`, `SchedulePaneInput`), `EditorOpen`, `ApplyEdits`, `Notify`, `PlaySound`, `OpenExternal`, `AgentAction`. `ilium-server/src/plugin_host/intent_routing.rs` does not exist.
- K2 pane kinds. `ilium_ipc::NewPaneKind::Plugin { kind_id, title }` exists on the wire only. `ilium-core` has no plugin pane content kind (no `kind_id` in `ilium-core/src/lib.rs`) and the client draws no plugin pane, so board and editor panes cannot leave the kernel.
- K3 popups. `ilium-client/src/plugin_host/popup.rs` (the `Mode::PluginPopup` host) draws message lines, `paragraph`, `choice` and `check-list` only. Text inputs and scrolling exist in the right-hand panel views (`plugin_host/view.rs`, `views.rs`) and not in modal popups. A kernel dialog with text entry or a long scrolling list therefore cannot become a plugin popup. Wanted: `popup.rs` renders and edits `Widget::TextInput`, `Widget::NumberInput` and `Widget::ScrollView` with the same state as `view.rs`.
- K4 kernel to plugin calls. The kernel call sites of these features run synchronously inside kernel loops (server detection loop, server IPC handlers, the client selection path). A plugin answers asynchronously through events. Wanted: a kernel-side call, for example `PluginHost::call_service(plugin: &str, service: &str, payload_json: &str, deadline: Duration) -> Result<String, CallError>` on the server and `App::call_plugin_service(...)` on the client, with `CallError::Unavailable` when the plugin is disabled so the kernel feature is off while the plugin is off.
- K5 imports that are not equipped on a running plugin instance (`ilium-plugin-host/src/runtime.rs` instance import set and `wiring/wave_two.rs`): `clipboard` (`ClipboardImport` exists, used only by the testing harness), `editor` (`EditorImport`, harness only), `client-requests` (harness only). Skeletons without a backend: `inference` (`InferenceImport::new(ids)`, no provider call), `sounds` (`SoundsImport`), `audio`. `workspace` is an in-memory `WorkspaceImport` that is not backed by the kernel custody in `ilium-server/src/workspace*.rs`.
- K6 tree and terminal chrome. `ilium-client/src/terminal_context_menu.rs` lists no plugin entries and contributed toolbar buttons and row actions are not drawn (G6 is not built).
- K7 command line environment. There is no env or argv import in `wit/host/`. The `cli` import offers `caller-pane` and `selected-panes` only. A moved `ilium chat` needs `ILIUM_CHATROOM_AUTHOR`, `AGENT_NAME`, `ILIUM_PANE_ID`, the pane worktree variable `ilium_ipc::pane_env::WORKTREE`, optional hook JSON on standard input (`stdin: optional`; the manifest says `none`), and a project scope that reaches the main checkout of a linked worktree (the `fs` project scope is rooted at `Backends::project_dir` only).
- K8 settings. A contributed row is stored under `[plugins."<id>"]` in `config.toml`. The kernel tabs these plugins own are `[git]`, `[kanban_board]`, `[editor]`, `[text_triggers]`, `[triggers]` and `[icons]`, read by kernel code that must keep working (server workspace setup, `ilium-client/src/config.rs`). `settings.read-kernel:<tab>` and `settings.write-kernel:<tab>` work through `ConfigFileSettings`, but the running client and server do not reload after a plugin write and no `kernel-settings-changed` event exists (contract 20.5). Moving a tab needs both a migration of the stored keys and kernel readers that read the plugin store.
- K9 manual lock. The manual page and its REQ-tagged tests pin the manifests: for example `plugins/core/worktrees/tests/features/manifest.rs` line 240 asserts there is no `settings` contribution, and `plugins/core/text-triggers/tests/features/manifest.rs` asserts the exact grant lists. The group plan's contributions (settings rows with the built-in key names, extra grants, extension entries, a `plan` service) contradict those pins. They need a decision to change the manual page and the pins together; `tools/req_coverage.py` stays at exit 0 only while tagged tests are kept.

What the foundation does provide today (so a later move can use it): editable plugin settings rows in the Plugins list (`plugin_host/settings_rows.rs`), text input and scrolling in panel views (`plugin_host/view.rs`), link detectors (`plugin_host/links.rs`), the `process`, `fs`, `http` and `jobs` imports per instance, topics and services across sides, `SignalPane` and forwarded `OpenView`/`CloseView`, and `ilium <name>` routing to plugin CLI commands (`ilium/src/plugin_cli.rs`).
