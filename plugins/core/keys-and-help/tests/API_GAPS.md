# API gaps found by the keys-and-help feature tests

Items the tests use that the skeleton lacks. Each is written against the manual; none was added to src/.

- ilium-plugin-testkit: `impl FakeHost { pub fn keymap(&mut self) -> &mut FakeKeymap }` with `pub fn set_bindings(&mut self, bindings: Vec<ilium_plugin_sdk::host::keymap::Binding>)` and `pub fn set_label(&mut self, chord: &str, label: &str)` (the answer of `keymap.chord-label`); F-007, F-010; the plugin reads `keymap.bindings` and `chord_label`, which need seeded data.
- ilium-plugin-testkit: `impl FakeHost { pub fn kernel_settings(&mut self) -> &mut FakeKernelSettings }` with `pub fn set_tab(&mut self, tab: &str, values: serde_json::Value)`, `pub fn tab(&self, tab: &str) -> Option<serde_json::Value>` and `pub fn writes(&self) -> Vec<(String, String, String)>` (tab, key, JSON value of each `kernel-settings.write`); F-007, COR-033.
- ilium-plugin-testkit: `impl FakeHost { pub fn help(&mut self) -> &mut FakeHelp }` with `pub fn add_topic(&mut self, global_id: &str, markdown: &str)` backing `help.topic`; F-010.
- ilium-plugin-testkit: `impl FakeHost { pub fn plugins(&mut self) -> &mut FakePlugins }` with `pub fn add_simple(&mut self, id: &str, name: &str, enabled: bool)`, `pub fn mark_failed(&mut self, id: &str)`, `pub fn set_enabled_calls(&self) -> Vec<(String, bool)>` and `pub fn fail_next_set_enabled(&mut self, error: PluginError)` backing `plugins.list` and `plugins.set-enabled`; F-010.
- ilium-plugin-testkit: `impl FakeHost { pub fn invalidated(&self) -> Vec<ViewTarget> }` listing the views the plugin invalidated through `ui.invalidate`, one entry per coalesced redraw; F-010.
- ilium-plugin-testkit: `impl FakeHost { pub fn published_topics(&self) -> Vec<(String, serde_json::Value)> }` listing (global topic id, payload) of every topic publication; F-010.
- ilium-plugin-testkit: `impl FakeSession { pub fn set_enabled(&mut self, plugin: &str, enabled: bool) -> &mut FakeSession }` turning a plugin off or on as the plugin manager does; COR-022.
- ilium-plugin-testkit: `impl FakeSession { pub fn collected(&mut self, point: &str) -> Vec<serde_json::Value> }` returning the `entry` payloads of a collect point in the documented order (user order, tier band, priority, plugin id, extension id); F-010.
- ilium-plugin-testkit: `impl FakeSession { pub fn grant_service(&mut self, caller: &str, service: &str) }` granting `services.use:<service>` to an ad-hoc caller id; F-010.
- ilium-plugin-testkit: `FakeSettings` must return the manifest default for a keybinding row key (`show_keys` is `"?"` before any write) and accept `set("show_keys", ...)`; F-007.
- plugins/core/keys-and-help: file `help/keys-overview.md` (named by `contributes.help[0].file`) does not exist in the crate; F-010.
- plugins/core/keys-and-help: `KeysAndHelpClient` needs `exports = ["views", "service-provider"]` and the manifest needs `services.provide:ilium.core.keys-and-help/bindings`, `contributes.services.provides`, `contributes.topics.publishes`, `contributes.extensionPoints` (`key-hints`, `help-sources`) and the `extensions.provide:ilium.core.keys-and-help/<point>` grants, because the page states them (Extension points section). The manifest block of the page lacks them; the manual must be reconciled with the manifest or the tests `points_010_the_manifest_of_the_owner_*` and `service_010_the_manifest_*` will stay red. F-010.
- ilium-plugin-testkit: `core_stubs::CoreStub` for `keys-and-help` must list extension points `key-hints`, `help-sources` and service `bindings` (short names, as the test expects); F-010.
