# API gaps found by the agent-detect features tests

- ilium-plugin-testkit: `impl FakeTree { pub fn set_screen(&mut self, id: u64, text: &str) }` (COR-011): sets the visible screen text of a fake terminal pane, which the plugin reads through `panes.read` before it answers an interstitial prompt.
- ilium-plugin-testkit: `impl FakeHost { pub fn contribute_extension(&mut self, point: &str, id: &str, priority: i32, entry: serde_json::Value) }` (F-027): registers a contribution to an extension point the plugin owns (here `ilium.core.agent-detect/activity-rules`), as a package manifest would.
- ilium-plugin-testkit: `impl FakeHost { pub fn call_own_service(&mut self, name: &str, request_json: &str) -> Result<String, PluginError> }` (F-026): calls a service the plugin under test offers (`ilium.core.agent-detect/state`, methods `get` and `list`) and returns the `done` reply text; `FakeSession::call_service` needs the plugin installed as a package.
- ilium-plugin-testkit: `impl FakeHost { pub fn published_topics(&self) -> Vec<(String, String)> }` (F-027): `(topic, payload_json)` of every topic publication the plugin made, in order.
- ilium-plugin-testkit: `FakeSettings` must serve the kernel `[ui]` and `[detection]` keys of the tab `agent-monitoring` with the defaults and validation of the existing loader (F-030, F-034, COR-011): `ui.agent_monitoring_mode` ("normal"), `ui.agent_identifier_mode` ("icon"), `ui.claude_agent_icon` ("crab"), `ui.codex_agent_icon` ("turtle"), `ui.antigravity_agent_icon` ("atom"), `ui.attention_running_indicator` ("icon"), `detection.working_poll_seconds` (10), `detection.idle_poll_seconds` (45), `detection.auto_answer_interstitial_prompts` (true); a refused value fails with `invalid-argument` and the loader message (ilium-client/src/config.rs `ConfigLoadError`).
- ilium-plugin-testkit: `impl FakeHost { pub fn classify(&mut self, signature: &str, screen: DetectorScreen) -> Classification; pub fn identify(&mut self, processes: Vec<DetectorProcess>) -> Option<String> }` (F-026, F-027): call the `detector` export of the activated plugin so that contributed `activity-rules` apply. The other tests call `AgentDetectServer::default().identify/classify` directly, which needs no host.
- ilium-plugin-api / manual: the JSON shape of the service `ilium.core.agent-detect/state` requests (`{"method": "list"}` and `{"method": "get", "pane": <u64>}`) and of its list entries (`pane`, `signature`, `activity`) is not specified; the tests assume it (F-026). The manual must state it or the tests change with it.
- ilium-plugin-api / manual: the text format of `Classification.goal` (goal text or goal state word) is not specified; the tests only assert presence or absence of a goal (F-029). The mapping of the activities waiting-background, background-task-still-running and settling onto the six-case WIT `agent-activity` is also not specified; the tests assert only that those screens are not reported idle or done (F-027).
- ilium-plugin-core-agent-detect (skeleton): the plugin implements no `HookHandler` (`activity-rules`, `classify`), no `ServiceProvider` (`state`) and the client side no `Views` for the panel `agent-detect.panel` (F-027, F-034).
- ilium-plugin-api / manual: the manifest has no `contributes.commands`, settings rows, keybindings or `extensions`, `services`, `topics` blocks although the page names the points, the service and the topic; the page says the manifest is exact, so those contributions are tested only against the page text (COR-050).
