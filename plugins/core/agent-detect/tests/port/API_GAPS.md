# API gaps found while porting the agent-detect originals

- ilium_plugin_sdk::generated::exports::detector (detector export): `fn is_prompt_ready(signature: String, screen: DetectorScreen, cursor: Option<(u16, u16)>) -> bool` and `fn is_fresh_screen(screen: DetectorScreen) -> bool` (F-026): the prompt-readiness and fresh-screen originals (antigravity_prompt_readiness_requires_the_empty_composer_cursor, codex_composer_hint_under_a_live_modal_is_not_prompt_ready, codex_composer_placeholder_is_not_a_selection_prompt, codex_cursor_aware_readiness_requires_the_first_input_cell, codex_dirty_composer_is_not_prompt_ready, codex_numbered_choice_cursor_is_not_a_free_form_composer, legacy_codex_box_must_be_visibly_empty, prompt_readiness_requires_each_provider_visible_composer, fresh_screen_detection_covers_all_builtin_agents_without_treating_idle_as_fresh) have no export to call.
- ilium_plugin_sdk::generated::exports::detector::Classification: `evidence: ActivityEvidence` and `matched_line: Option<String>` (F-026): detailed_classification_retains_the_bounded_line_that_justified_it, detailed_goal_classification_retains_the_provider_status_line, current_live_status_keeps_generic_and_claude_evidence_distinct, background_diagnostics_choose_the_newest_eligible_matching_line, newest_status_evidence_remains_bounded_and_control_character_free, still_running_suffix_without_a_done_clock_remains_settling assert them.
- ilium_plugin_sdk::generated::exports::detector::AgentActivity: variants `WaitingBackground`, `BackgroundTaskStillRunning`, `Settling` (F-026): the WIT enum has six cases, so the twins assert only "not idle, done or none" for these states.
- ilium_plugin_sdk::generated::exports::detector::Classification: `goal: Option<GoalPhase>` with `Active, Paused, Blocked, UsageLimited, Reached` (F-028): `goal` is a free string, so phase mapping cannot be asserted.
- ilium_plugin_sdk::testing::FakeTree: `fn set_screen(&mut self, id: u64, text: &str)` (F-029): listed in features/API_GAPS.md too; the interstitial twins use it.
- ilium_plugin_sdk::testing: `fn identify_with_tree(&mut self, tree: ProcessTree) -> Option<ProcessSelection>` (F-027): pid-level selection (launcher ancestor identity, agent_identity_guard, identify_agent descendant search) is not expressible with a flat process list; those originals are skipped.
- ilium-plugin-core-agent-detect (client): no plugin surface for the client-core attention-target ordering, terminal-activity phases, value-detection editing, render-cache mirrors, the kernel detection loop (tiers, debounce, completion samples, session claims), IPC handlers/wire types, foreground-observation probes and statusline delivery (F-026..F-034, F-111): the manual keeps the loop, IPC and PTY in the kernel ("The loop itself stays in the kernel"), so those originals have no FakeHost twin and are reported as skipped.
- ilium-plugin-core-agent-detect: tests/port/kernel_ports.rs twins of kernel-owned originals (detection loop, IPC, client core, probes) assert only classify/identify/decoration consequences plus the manual boundary statements; no plugin API exists for their subject (F-026..F-034).
