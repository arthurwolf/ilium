# API gaps found by the tree features tests

- ilium-plugin-testkit: `impl FakeTree { pub fn set_locked(&mut self, id: u64, locked: bool) }` (F-006): sets `NodeView.locked` of a fake node and delivers `tree-changed`; needed to test that locked groups are not auto-removed.
- ilium-plugin-testkit: `impl FakeTree { pub fn set_metadata(&mut self, id: u64, bytes: Vec<u8>) }` (F-006): writes the `tree.metadata` blob of a fake node (bookmark flag: `[1]`) and delivers `tree-changed`.
- ilium-plugin-testkit: `impl FakeTree { pub fn metadata(&self, id: u64) -> Option<Vec<u8>> }` (F-006): reads the metadata blob back, to assert the bookmark byte after the bookmarks service ran.
- ilium-plugin-testkit: `impl FakeHost { pub fn published_topics(&self) -> Vec<(String, String)> }` (topic `ilium.core.tree/changed`): `(topic, payload_json)` of every topic publication the plugin made, in order.
- ilium-plugin-testkit: `FakeSettings` must serve the kernel `[ui]` settings the plugin reads (`ui.auto_remove_empty_groups` default true, `ui.lock_closed_enabled` default true, both boolean; a non-boolean value fails with `invalid-argument`), see reference-feature-traceability.md rows F-005 and F-006 (F-006).
- ilium-plugin-testkit: a way to invoke an extension point the plugin owns with contributors (`before-move`, `before-close` veto hooks, `node-sorts` collect), for example `FakeSession::call_extension(point: &str, payload_json: &str) -> Result<Vec<String>, HarnessError>` (F-004, F-005); the tests only read the page table until it exists.
- ilium-plugin-api / manual: the JSON request shape of the service `ilium.core.tree/bookmarks` (operations list, add, remove) is not specified; the tests assume `{"op": "list"}` and `{"op": "add"|"remove", "node": <u64>}` (F-006). The manual must state the shape or the tests change with it.
- ilium-plugin-api / manual: the client command ids of the tree toolbar (New group, New folder) and the menu item ids beyond `rename`, `lock`, `close` (`unlock` is assumed from the user docs) are not in the manifest, which has no `contributes` block; the page says the manifest is exact, so the commands, settings rows and `extensions.provide:*`, `services.offer`, `topics` grants the page text mentions are untested (F-002, F-004).
- ilium-plugin-api / manual: the JSON answer of the bookmarks service `list` is not specified; the list test assumes a bare array of node ids or `{"bookmarks": [...]}` with ids as numbers or `{"node": id}` (F-006).
