# API gaps found by the tree port twins

- ilium-plugin-testkit / manual: the Order By modes (manual, age, cost, type, name) and the split-member exemption are kernel behaviour; the plugin supplies the `order` sort keys and the pure ordering module (`src/ordering.rs`, tested directly), so the twins in tests/port/tree_ordering.rs check key-derived order only. Cost ranks and type grouping at plugin level need `FakeSession::call_extension("node-sorts", ...)`.
- Foundation G2 (settings rows read-only) and testkit: `FakeSettings` knows only declared rows plus four kernel `ui` keys, so `ui.tree_order`, `ui.auto_remove_empty_groups` and `ui.lock_closed_enabled` cannot be set in a test. The port twin `port_022_choosing_an_order_item_writes_the_tree_order_setting` is `#[ignore]`d for that reason.
- Foundation G16: the `tree_orderings` contribution allows at most 4 entries with kebab-case ids (no underscore), but the six Order By ids are `age_ascending` and similar; the contribution is not declared and `ordering.rs` is the plugin copy of the policy until it can be.
- Testkit: `HostIntentsHost::submit` is not modelled (it returns an error), so a service handler queues its intents and sends them with the next `on_events` batch; the fake cannot show them earlier. A service handler also cannot return `Err`, so errors travel as `{"error": ...}` payloads.

## Re-check of the foundation against the tree (2026-11-14): what still blocks the moves

- New group dialog: moved (2026-11-14). The popup host now draws `TextInput`, so the dialog is the plugin popup `new-group` (`src/new_group.rs`, command `ilium.core.tree/new-group`, answer message `create-group` to the server side, intent `CreateGroup`); the kernel `Mode::CreateGroup` and its drawing, key, mouse and layout code are cut in `docs/tasks/02-cuts/tree.md` hunks 5 to 32. Still open: the Rename dialog, which shares `Mode::Rename` with diagnostic and board prompts, so it cannot be cut as one mode; wanted: a rename popup (`TextInput`, intent `RenameNode`) and a hunk per `Mode::Rename` entry point.
- `Intent::CreateFolder` is routed by the server facade now (`create_folder` in `ilium-server/src/plugin_host/intent_routing.rs`); the New folder entry still opens the kernel folder explorer overlay (`Mode::FolderExplorer`, a path picker), and no plugin popup widget picks a folder path.
- `tree_orderings`: there is no `ilium-client/src/contrib/` consumer, and `tree_ui.rs` calls `tree_ordering::ordered_children_ranked` synchronously in the draw path; wanted: `contrib::tree_orderings(&ClientPlugins) -> Vec<OrderingContribution>` plus per-node sort keys read from node metadata, and normalised ids (`age_ascending` vs `age-ascending`).
- `tree_toolbar_settings.rs`: `settings_ui.rs` shows no plugin-contributed Settings tab; wanted: a contributed `tab` page drawn through `plugin_host/settings_rows.rs`.
- `recent_activity.rs` throttles the per-pane output event on the server hot path (`ipc/handlers.rs record_recent_activity`); it cannot be a plugin without a synchronous server call.
