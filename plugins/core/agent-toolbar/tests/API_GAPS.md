# API gaps found by the agent-toolbar features tests

- ilium-plugin-testkit: `impl FakeHost { pub fn agents(&mut self) -> &mut FakeAgents }` with `impl FakeAgents { pub fn set_context_used_tokens(&mut self, pane: u64, tokens: u32); pub fn set_transcript_verified(&mut self, pane: u64, verified: bool) }` (F-035, F-081): the fake of the `agent.transcript` primitive; the model/context message needs the used-token count of a pane, and the compact routing needs to know whether the pane has a verified transcript.
- ilium-plugin-testkit: `impl FakeHost { pub fn journal(&mut self) -> &mut FakeJournal }` with `impl FakeJournal { pub fn append(&mut self, pane: u64, at_ms: u64, kind: &str, detail: &str) }` (F-035): the fake of `journal.read`; the page sample maps each entry to `{at, kind, detail}` but `ilium:host/journal.journal-entry` has `payload_json`, not `detail`, so the fake must define how `detail` is stored (the tests assume it is what the plugin returns as `detail`).
- ilium-plugin-testkit: `impl FakeHost { pub fn extensions(&mut self) -> &mut FakeExtensions }` with `impl FakeExtensions { pub fn contribute(&mut self, point: &str, id: &str, priority: i32, entry_json: &str) }` (F-035): feeds a contribution of another plugin to an extension point the plugin owns (`ilium.core.agent-toolbar/toolbar-actions`).
- ilium-plugin-testkit: `FakeSettings` must serve the kernel `[ui]` keys `agent_toolbar_enabled`, `show_toolbar_labels`, `last_prompt_enabled` (booleans, defaults true, true, true), `last_prompt_max_lines` (integer 1 to 20, default 4, out-of-range message `ui.last_prompt_max_lines = <n> must be between 1 and 20`, code `invalid-argument`) and `[remote_compaction] enabled` (boolean, default false) under the keys `ui.<key>` and `remote_compaction.enabled` (F-033, F-035, F-081, COR-011).
- ilium-plugin-testkit: `FakeHost::render(ViewTarget::Pane(id), ..)` must draw the kernel pane frame with the plugin's frame slots (`prompt` banner, `model` header text, `recover` footer row) and the agent toolbar for a pane whose `AgentView.signature` is set; `ViewTarget::Popup("history")` must render the popup the client opens with `ui::open_popup_with("history", ..)` (F-033, F-035). The tests assume the frame is the box-drawing frame of the page figure.
- ilium-plugin-sdk-core: `impl std::fmt::Display for NodeId` and `impl std::str::FromStr for NodeId` (page samples call `pane.to_string()` and `payload.parse::<NodeId>()`; the generated `NodeId(pub u64)` has neither) (F-035).
- ilium-plugin-sdk-core: `RichText::plain(text)` is used by the page samples, but `RichText` is the alias `Vec<RichSpan>` and an inherent `plain` cannot exist on it; the manual or the SDK needs a constructor function (for example `ilium_plugin_sdk::types::rich_text_plain(&str) -> RichText`) (F-033). The tests build the span by hand.
- manual: the channel and payload of the debug-history reply are not specified; the tests assume the server answers on channel `history` of the client side with a JSON array of `{at, kind, detail}` (`at` in milliseconds since the epoch, shown as `HH:MM:SS` UTC) read with `since = now - 3,600,000` and `limit = 50` (F-035).
- manual: the command `compact` with remote compaction on is assumed to start `ilium.core.compaction/compact` through an `invoke-command` intent from the client; the page does not name the call or its arguments (F-081).
- manual: the request and reply of the service `ilium.core.agent-toolbar/last-prompt` are not specified; the tests assume the request `{"pane": <u64>}`, the reply JSON string of the prompt (`null` without a prompt) and `not-found` for an unknown pane (F-033).
- manual / ilium-plugin-api: the plugin skeleton declares `exports = []`, so no `service-provider`, and the manifest has no `extensions.provide:ilium.core.agent-toolbar/<point>` grants, no `services.offer` entry and no `messages` grant although the page uses `message` intents between its sides and the service `last-prompt`; the page says the manifest is exact, so these are untested at manifest level (COR-050).
- manual: reference-feature-traceability.md lists `terminal.write` as a grant of F-035 and F-081, but the Complete manifest of the page does not (it has `agent.control` and `ui.chrome`); the tests follow the manifest.
- manual: the popover figure of the page is 47 columns wide although its caption says 48; the golden `golden/debug_history_47.txt` and the render test use 47.
- manual: how the goal text of `agent-goal-changed` is shown "under the last-prompt banner" (slot id, content) is not specified; the tests only assert that the event submits nothing.
