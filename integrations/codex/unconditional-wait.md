# Native Codex integration for Ilium waits

[`unconditional-wait-v0.167.0.patch`](unconditional-wait-v0.167.0.patch) targets the pristine Codex 0.167.0 release source. Apply from the upstream repository root. This is an authored Ilium integration, separate from the upstream package and from any running invocation.

## Contract

Call native `ilium_wait` directly when its tool catalog exposes it. The tool uses `DirectModelOnly` exposure even in CodeModeOnly configurations, and its handler also rejects nested Code Mode calls. Never wrap it in `functions.exec`, a terminal snapshot, or another yielding execution cell. Existing sandboxing, command approval, permission hooks, process ownership, bounded output and cancellation machinery remain responsible for execution.

Provide exactly one of `monitor_id` or nonempty `probe_command`. An existing monitor is observed with `ilium progress wait`; a probe is registered with `ilium progress set --wait`, without replacing other monitors. `interval_seconds`, from 1 to 86400, configures probe frequency only. Unknown fields are rejected, including timeout, deadline and yield controls. The observer requires the local POSIX environment of the Ilium pane; remote and Windows execution are unsupported. Normal nonblocking `ilium progress set` remains available.

The internal execution lifetime collects bounded output with **no logical deadline**. Ordinary interactive terminal snapshots and bounded one-shot commands retain their deadlines. Cancellation ends the wait command's owned process handle; it does not cancel or restart the monitored job or its server-owned probe. CLI exit codes and output preserve done, task error, monitor failure and cleared distinctions, including composer duplicate-delivery information. Recover an interrupted observer by the exact monitor/job identity; observation loss never authorizes another job.

Finish independent work before waiting. One initial message identifying the task and pending result is enough; healthy unchanged progress does not require commentary, model checks or a new wait call. New user input, explicit interruption, approval interactions, real outcomes and observation failures remain actionable. Waiting does not pause, complete or replace the user's goal.

If the native tool is absent, keep the same blocking CLI/session handle at the adapter's greatest supported wait. This fallback is best effort: continuing a capped handle can spend another inference request. Project instructions cannot override a higher-priority injected requirement for recurring commentary. This patch does not change the hosted outer adapter or arbitrary goal/check-in schedulers, and makes no universal claim about shell-polling bypasses.

## Build and qualification

All compilation, tests and checks go through `ni-build` on `ni-vm` using isolated source and target folders. Do not inherit historical local-build exceptions. The patch normalizes 171 source-only workspace package versions and their dependency references from 0.0.0 to 0.167.0; the 1,308 external package records are unchanged. For dispatcher source packaging, materialize the upstream `codex-rs/vendor/bubblewrap/LICENSE` symlink from its same-tree `COPYING` contents in the isolated build input.

The patch includes native handler validation tests, direct-only registration tests for all three tool modes, and controlled-time process-output tests. The collector tests cross three ordinary snapshot boundaries without returning, preserve final output, retain the byte cap, test output-closure/exit races, and verify that ordinary snapshots still return on their deadlines. Dropping an output collector leaves process output recoverable. These focused tests are separate from full observer process cancellation and live scheduler acceptance.

Required checks include the focused native tests (`cargo test -p codex-core --lib ilium_wait`), ordinary unified-exec regressions, relevant Clippy, formatting, a release build, and an isolated runtime trial with a real Ilium monitor. Count actual model requests before entry, throughout the pending interval, and after completion; record any independent scheduler wake separately. Test user interruption, observer disconnect and terminal-outcome races while retaining job identity. A quiet terminal or passing collector test does not prove zero inference or that the monitored job survived observer cancellation.

Installation requires explicit authorization. A built artifact, replacement of an on-disk package binary, the executable loaded by a live process, and that invocation's exposed tool catalog are separate facts. Replacing a binary never changes an existing invocation. Verification uses task-owned processes and isolated application state; it does not replace mainstream binaries or restart the user's live sessions or jobs.

## Current acceptance status

The 0.167.0 patch applies cleanly to all 12 affected upstream paths. Remote formatting passed. All 12 authored native wait tests and ordinary unified-exec regressions passed together: 96 tests, zero failures. `cargo clippy -p codex-core --all-targets -- -D warnings` passed. These checks have verified dispatcher receipts for the same source inventory. A broader 2,903-test run aborted on a stack overflow in `agent::control::tests::ensure_v2_child_loaded_preserves_evicted_parent_authority` before the native tests ran; this does not establish whether that failure predates the patch.

A real Codex app-server built through the dispatcher with upstream `dev-small` and eight compiler jobs completed in 20 minutes 14 seconds. Its loaded executable SHA-256 was `b0fe434a3d64c8c16a156fcc72cc46623c63b1fff28381a4733f34c502532c0b`, matching the verified artifact, version 0.167.0 and source inventory used by the focused tests and Clippy. The actual provider-facing tool catalog exposed one native `ilium_wait`; its schema SHA-256 was `f01f7ba3fccd9e1a39b08d4903f34e1affdb998a63c263693a195373478cf99c`. Standard release qualification remains unverified: two full CLI release attempts exhausted their 16 GiB memory limit, and a single-worker app-server release attempt reached the remote watchdog's 10,800-second command limit. The successful unoptimized build is the runtime-test substitute, not a qualified release build.

With goals enabled, a real isolated Codex invocation and real Ilium monitor, the native observer remained pending for 905.87 seconds, crossing three ordinary adapter boundaries with zero recurring model requests, one job, one observer and one terminal tool result. The matched fallback on the same executable needed three continuation requests at approximately 30, 330 and 630 seconds. Native made three total requests (entry, terminal processing, fixture-goal completion); fallback made six. The installed unpatched 0.167.0 baseline likewise needed three pending continuations. Server probes continued independently: 885 native and 886 fallback probe executions. This sample measures zero native recurring waiting requests versus approximately 11.9 fallback requests per waiting hour; it does not extrapolate universal workload savings.

Native runtime tests also verified success, task-error exit distinction, and explicit turn interruption in 41 milliseconds. Interruption removed the actual CLI observer, kept the goal active and the same task process alive, and a new invocation reattached to that monitor and recovered the result with one job start. Native success and error delivery reached the runtime approximately 1.09 and 0.94 seconds after the task recorded its outcome, within the configured one-second probe interval allowance. The isolated server and client were existing installed Ilium test executables; no newly built Ilium candidate is implied.

Additional native Codex trials verified observer connection loss (terminated CLI observer, exit 143) and recovery; two simultaneous monitors with identical messages; isolated server restart (old observer exit 1), restored monitor lookup by job identity and recovery; failed observation (exit 4 while the task remained running); and explicit monitor clear (exit 5). Every recovery retained the same task process with one job start. A late native observer retrieved the restored terminal outcome without another probe execution. Clearing a running monitor requires the CLI's explicit `--running` flag and the exact owned monitor ID.

Native cancellation/completion acceptance covers both deterministic orderings. Cancellation before job release removed only the observer and preserved later recovery. For completion first, a verified pending CLI observer received the real task result; the synthetic provider held its next response at a barrier, then turn interruption completed in 15 milliseconds with the goal still active. A new native invocation recovered the retained result; the probe count stayed 15 before and after the late read. This verifies the terminal-delivery boundary without claiming exhaustive coverage of all possible interleavings. Controlled-time native tests separately cover output-closure/exit races and collector drop.

The hosted session used to author this revision does not expose native `ilium_wait`; hosted zero-inference prevention is unsupported here. Runtime request counts above used an instrumented synthetic loopback model provider with actual Codex requests and enabled goal scheduling. They do not establish real-model tool selection, provider token deltas, billing or subscription usage. The mainstream Codex launcher and live Ilium sessions were unchanged.
