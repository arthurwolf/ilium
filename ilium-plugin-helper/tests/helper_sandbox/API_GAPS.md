# API gaps of lane helper-sandbox

- ilium-plugin-helper dev-dependencies: none needed beyond the crate's own dependencies; tests use std only. For host-side supervision tests (HST-154, HST-162..170, SEC-050..052 counting) the lane needs `ilium-plugin-host = { path = "../ilium-plugin-host", features = ["testing"] }` as dev-dependency (HST-164, HST-165, HST-166, HST-170); until then those rules are asserted through the manual text (doc_ tests).
- ilium-plugin-helper wire format (HST-155, SEC-052): the manual says "length-prefixed `bincode`" without the width of the prefix, tag numbering or field layout. Tests assume: u32 little-endian length, bincode-1 fixed-width integers, enum tag u32 in table order (Hello 0, Instantiate 1, InstantiateFailed 2, Ready 3, CallExport 4, CallResult 5, HostCall 6, HostReply 7, Cancel 8, Shutdown 9, Heartbeat 10, Log 11), fields as in `tests/helper_sandbox/support.rs`. Needed: `pub mod ilium_plugin_helper::protocol` types `Hello { protocol_version: u32, fingerprint: String, build: String }`, `Instantiate`, `InstantiateFailed`, `CallExport`, `CallResult`, `HostCall`, `HostReply`, `Cancel`, `Shutdown`, `Heartbeat`, `Log` plus `pub fn write_frame(w: &mut impl Write, m: &Message)` and `pub fn read_frame(r: &mut impl Read) -> Result<Message, HelperError>`; HST-155. The skeleton `HelperRequest`/`HelperReply`/`Ready` do not match the manual's message table.
- ilium-plugin-helper channel (HST-153): main.rs serves on stdin and stdout; the manual says the child keeps only the inherited socketpair and stdio on /dev/null. Tests use fd 0/1 as the channel (pipes or a socketpair). Needed: a documented channel fd (or the spec decision that stdin/stdout are the socketpair ends).
- ilium-plugin-helper `sandbox::apply(&SandboxPolicy) -> Result<(), HelperError>` (SEC-021..029, SEC-067): tests apply it in a re-executed copy of the test binary and expect that fds 0 to 2 stay open, that granted `write_paths` are mounted at the same absolute path with `noexec,nosuid,nodev`, that the environment is rebuilt to the SEC-027 allowlist, and that no other namespace work is delegated to the spawner. If the implementation applies namespaces only in the spawn path, add `pub fn apply_in_current_process(policy)` or equivalent; SEC-021.
- ilium-plugin-helper test hook (SEC-065): environment variable `ILIUM_PLUGIN_FORCE_NO_CGROUP=1` makes `apply` behave as if no cgroup controller is delegated, so the setrlimit fallback is observable in `/proc/self/limits`; SEC-065.
- Guest fixtures (built by lane conformance, loaded from `ILIUM_PLUGIN_FIXTURE_DIR` or `ilium-plugin-conformance/fixtures/wasm/<name>.wasm`): `conformance-probe` (exports `ping`, `forward-1`, `forward-5`, `forward-1000`, `read-other-plugin-data`), `fuel-burn` (`spin`), `ui-stress` (`bulk-10-mib`), `grant-matrix` (`import-<family>` for codec, vector, clock.now, random, log, storage, fs, http, process, ui, messages, timers, jobs, inference, clipboard), `hostile-escape` (`run-escape-suite` returns `all-denied`, `allocate-past-limit`, `fork-bomb` returns `EAGAIN`, `read-ssh-dir`), `hostile-suite` (exports named in `reference_sandbox_hatches.rs`, `reference_sandbox_files.rs`, `reference_sandbox_trust.rs`; each performs one import with the call argument and returns the error code it received as UTF-8 bytes), `imports-wasi-sockets`, `imports-wasi-http`; HST-157..163, SEC-025, SEC-029, SEC-031..066.
- Host-policy requirements SEC-031..035, SEC-040..046, SEC-058..064, SEC-066 are decided by the host. Their behavioural tests belong to a host or security lane with `HostHarness`; this lane checks forwarding with unchanged arguments plus the manual text.
- Non-x86_64 targets: `probe_child.rs` issues raw syscalls only on x86_64; elsewhere the SEC-067 probes return -38 and fail; a per-arch syscall table is needed; SEC-067.
