### Added
- Custom agent status icons with ordered rules, screen-text matching, configurable visuals and live and demo tree previews.
- Custom status rules can test the task's time estimate (`eta-known`, `eta-below-minutes`), a frozen pane and the session's tracked spend (`session-cost-above`); every condition now carries a category, label and one-sentence explanation that the rule editor reads from one shared registry.
- Custom status rules can explain themselves: the rule engine reports, per rule, which conditions held, failed or were not observed, and renders a one-line reason such as `Custom rule 3 "Goal paused": goal is paused AND NOT agent is working`.
- A shared catalogue of thirty synthetic pane situations exercises every shipped default rule and every condition in the engine's tests.
- The control API accepts `ui.agent_monitoring_mode` (`normal`, `attention`, `custom`) for get, set and adjust.
- Hovering the status cell of a pane in Custom mode shows which rule chose the icon and why (`Why: Custom rule 3 "Goal paused": ...`), or why no rule matched, including how many rules depended on a fact that was not observed.
- Custom status rules can test whether a pane is bookmarked (`pane-bookmarked`), has queued prompts (`prompts-queued`), runs a custom agent (`other-agent`, or a named one such as `agent is aider`) and whether the agent's activity could not be checked yet (`activity-unchecked`).
- Visual styles gain a `pulse` flag; the shipped approval and unread-completion rules set it, and a new default rule `parked-progress-unsteady` tints a parked task's moon in the warning colour while its monitor is unsteady.
- `[status_rules]` carries a format `version = 1`; a file written by a newer format loads with a warning.
- Custom status rules can test whether a pane's terminal holds keyboard focus (`pane-focused`); the tree, the hover explanation and the rules editor derive every client-side fact (focus, frozen screen, spend, bookmark, queued prompts, activity freshness) from one shared builder, so they cannot disagree.
- Rule validation findings carry a typed kind and the AND group or condition they concern, a ruleset whose rules are all disabled gets a warning, and a `[status_rules]` table that loads with repairs or cannot be read writes one warning to the client log. Rules are read once when a client starts and are not shared between clients attached to the same session.
- Custom status rules can test whether a pane is selected in the tree (`pane-selected`), is on screen in the right panel (`pane-visible`, so `NOT pane is on screen` flags agents you are not looking at), whether its prompt queue is held on an interrupted delivery (`prompt-queue-held`), and whether the agent's context window is more than a given percentage full (`context-above-percent`, known once cost tracking has read the transcript).
- Seven Braille animation presets for custom status icons: `spinner`, `loop`, `dots`, `snake`, `bounce`, `pulse` and `bar-fill`.
- Six ready-made glyph-frame families for custom status icons (quarters, moon phases, clock hours, arrows, hearts, blocks); the rules editor's visual picker steps through them, and the hover text and rule summary name the family.
- The rules editor's New rule (`A` or `+ Add`) offers templates (Agent needs approval, Goal paused, Task failed, Blank), and Enter, `/` or ✎ on a condition without a value opens the condition list grouped by category with search and a one-sentence explanation of the highlighted entry.
- The rules editor pins an editable "Otherwise (no rule matches)" row under the list: Down past the last rule or a click selects it, and the icon controls then set the fallback icon.
- Rule rows in the editor colour each condition by category, show a warning badge when validation reports a problem with the rule and a green "N live" count of panes the rule currently decides.
- Documentation: a Custom status icons page lists every condition and the shipped default rules (generated tables checked against the engine by a test), the `[status_rules]` table and the `ui.agent_monitoring_mode` control key are documented, and Agent monitoring now describes the three display modes.
- Five help topics (AM-26 to AM-30) explain the rules editor, the rules list, conditions and icon, the icon designer and the rules preview.
- The agent-detect plugin settings tests and the feature traceability row record that `ui.agent_monitoring_mode` accepts `custom` and that Custom is client-owned, not a plugin display mode.

### Changed
- Agent Monitoring offers illustrated Normal, Attention and Custom display-mode choices.
- Shipped default rules mark approval, failures and unread results bold and the idle rule dim; the disabled screen-text example shows a bold red `!`.
- Loading `[status_rules]` keeps every readable rule: a broken rule is disabled with a reason, a duplicate identifier is renamed, an unreadable entry stays in `config.toml` untouched and survives later saves; enabled rules beyond the budget of 16 distinct screen patterns are disabled with a reason, and readable rules beyond the limit of 64 are not loaded but kept unchanged under `unloaded_rules` across saves; only an unreadable file or a table of the wrong shape still blocks custom rules.
- Rule edits apply at once and are written to `config.toml` 300 ms after the last change, immediately when the rules editor closes and on quit; a failed write keeps the edits, shows the error in the editor header and retries every 5 seconds.
- In Custom mode every pane row, including editors and boards, has exactly one three-cell status slot, so titles stay aligned and rules may target editors and boards; clicks and the blocking caution use that same slot.
- In Custom mode the tree redraws only for animations that a pane actually matched (never for the built-in Normal-mode spinners or for enabled but unmatched animated rules), so an idle tree schedules no periodic redraws; Motion `Reduced` slows custom animations to 2 frames per second and `Off` freezes them.
- Rule validation reports typed findings per rule (errors and warnings, including rules that an earlier rule makes unreachable) instead of one flat message, and a validated edit stays in memory even when the configuration write is refused.
- The Agent Monitoring display-mode cards share one selectable-card component with the Padding and Left-panel sizing cards (equal widths, pointer hover, focus frame); they adapt from full demo trees to short demos, description-only and stacked cards as the terminal narrows, and the Configure button shows how many rules exist and are enabled while Attention-only rows say so when another mode is active.
- The custom status-icon rules editor shows a Settings breadcrumb, numbered rules with a scrolling list (wheel, keyboard follows the selection), a Duplicate control, a twenty-step undo (`U` or `Ctrl+Z`), bracketed AND groups with a precedence legend, a screen-pattern region control (`L`: whole screen, first or last lines), a live "Matches N panes now" count, a plain-English reading of the selected rule, and a "Why this icon" box under the live tree that names the rule picking the focused pane's icon; the demo tree lists the engine's shared demo situations, an empty session shows guidance instead of a blank tree, and Esc steps back one column at a time while Backspace or Back returns to the page.
- Screen-text rule conditions now evaluate large but sparse panes (the 64 KiB budget counts the visible text, not the grid size), and a screen pattern the server refuses is reported as a typed refusal naming the offending pattern, keeping its conditions unknown instead of showing a generic server error.
- Custom status icons now pulse: a rule with `pulse` (the shipped approval and unread-completion rules) alternates its weight with a dim phase twice a second, once a second at Motion `Reduced`, and stays static at `Off`. Progress frames without a measurable percent show their first frame with the same pulse (dim and static at `Off`), so an unmeasured task no longer looks like 0 %; their monitor's degraded health tints them in the warning colour and a failed monitor in the danger colour. Only matched pulsing visuals wake the redraw clock.
- Custom status rule colours `danger`, `warning`, `success`, `info` and `muted` follow the active colour scheme: the dark scheme keeps the terminal's own colours, the light scheme uses darker tones that keep contrast.
- Rules editor keys: `Alt+↑↓`, `Ctrl+↑↓` or `[` `]` move a rule, `X` deletes, `Enter` on a rule edits it, `Shift+Tab` moves back a column, and letter keys work in either case; the key hints list the real bindings, columns keep a one-cell inner margin and rule names are joined to their badges by dotted leaders.

### Fixed
- A refused rules-editor edit from the keyboard (removing a rule's last condition, toggling case on a condition that is not a screen pattern) now shows its reason instead of silently doing nothing.
- Without a configuration folder, rules-editor edits apply for the session and the editor says they are not saved, instead of reverting the editor while the new rules stayed active.
- Custom status rules reject joined emoji sequences (zero-width joiners, skin-tone modifiers, tag characters such as flag subdivisions) in glyphs and frames, because terminals disagree on their width; a warning sign with a variation selector stays valid and keeps every title aligned. The tree redraws only for matched animations on rows it actually paints, so a collapsed group, a scrolled-out row or a hidden tree schedules no redraws.
