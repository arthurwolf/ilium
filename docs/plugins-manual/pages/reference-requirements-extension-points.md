## Requirements for extension points

Normative behaviour of extension points, hooks, collect points and the 66 core points.

The rows follow the format and the observation channels of the [requirements index](/pages/reference-requirements/). The id prefix is `EXT`.

| Id | Requirement | Source | Observable test |
|---|---|---|---|
| [EXT-001] | A plugin MUST declare at most 16 extension points and at most 64 extensions. More MUST fail the install with manifest.extension-limit. | [requestable limits](/pages/reference-errors-and-limits/#requestable-limits) | (install-error) declare 17 points -> manifest.extension-limit. |
| [EXT-002] | A caller MUST hold extensions.provide to own a point and extensions.contribute:<id> to contribute. Without the grant the call MUST fail with extension.not-granted and base code not-permitted. | [edge cases and error codes](/pages/api-extension-points/#edge-cases-and-error-codes) | (sync-return) run-hook without the grant -> err not-permitted, message starts "extension.not-granted: ". |
| [EXT-003] | An extension code MUST be carried by a plugin-error whose code is the mapped base code and whose message starts with the extension code, a colon and a space. | [edge cases and error codes](/pages/api-extension-points/#edge-cases-and-error-codes) | (sync-return) veto a hook -> message starts "extension.vetoed: com.example.quiet-hours: ". |
| [EXT-004] | A payload over 64 KiB MUST fail as extension.cap-exceeded with base code invalid-argument. A payload within the cap that fails payload_schema MUST fail as extension.schema-mismatch. | [edge cases and error codes](/pages/api-extension-points/#edge-cases-and-error-codes) | (sync-return) 65 KiB payload -> cap-exceeded. 1 KiB payload of the wrong shape -> schema-mismatch. No handler runs in either case. |
| [EXT-005] | When a chain reaches 100 ms the handlers not yet started MUST be skipped as pass, and each skip MUST be logged with extension.chain-cap and MUST NOT count as a breach. A handler that started before 100 ms MUST run until its own deadline_ms. | [edge cases and error codes](/pages/api-extension-points/#edge-cases-and-error-codes) | (log-line) point with deadline_ms 50 and four handlers of 40 ms each -> handlers 1 to 3 start at 0, 40 and 80 ms; handler 4 is skipped and logged extension.chain-cap. |
| [EXT-006] | A contribution that names a version MUST be active when its major equals the owner major and its minor is at least the requested minor and at most the owner minor; for major 0 the minor MUST be equal; the patch MUST be ignored. A contribution without a version MUST match any owner version. Otherwise it MUST be dormant. | [edge cases and error codes](/pages/api-extension-points/#edge-cases-and-error-codes) | (event-delivery) owner 1.2.0: @1.0.0 and @1.2.0 active, @1.3.0 and @2.0.0 dormant. Owner 0.1.2: @0.1.0 and @0.1.9 active, @0.2.0 dormant. |
| [EXT-007] | Two extensions on one point with the same priority MUST run in plugin id order, then in extension id order (byte-wise ASCII comparison). A T1 contribution MUST run before a T2 or T3 contribution of any priority, unless the user order says otherwise. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (event-delivery) two handlers at priority 10 -> the lower plugin id runs first. A T3 handler at priority 0 runs after a T1 handler at priority 90. |
| [EXT-008] | A lower priority number MUST run first. The user order from the Extensions tab, stored as a list of (plugin id, extension id) per point, MUST win over priority and tier. Items not in the list MUST follow it in default order. An update MUST keep the stored position and an uninstall MUST remove it. The same order MUST apply to list on collect points. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (event-delivery) user moves handler B above A -> B runs first. A contributor installed afterwards runs after both. Update A -> position kept. |
| [EXT-010] | observe MUST call all handlers and ignore replies. The outcome MUST be ok. | [hook modes](/pages/api-extension-points/#hook-modes) | (completion) observe hook with one replace reply -> ok and the reply logged as extension.reply-not-allowed. |
| [EXT-011] | transform MUST pass each handler the output of the previous one. take-reply MUST return the final payload only when at least one replace was accepted, and MUST return none otherwise. | [hook modes](/pages/api-extension-points/#hook-modes) | (completion) two replace handlers -> second sees the first output. Two handlers that both pass -> take-reply none. |
| [EXT-012] | veto MUST stop at the first refuse. The outcome MUST be refused(conflict) with extension.vetoed. Without a refuse the outcome MUST be ok. | [hook modes](/pages/api-extension-points/#hook-modes) | (completion) first handler refuses -> refused(conflict) and the second handler is not called. |
| [EXT-013] | first MUST stop at the first answer. take-reply MUST return the answer, or nothing when nobody answered. | [hook modes](/pages/api-extension-points/#hook-modes) | (completion) no handler answers -> ok and take-reply is nothing. |
| [EXT-014] | A reply that the mode does not allow MUST count as pass and MUST be logged as extension.reply-not-allowed. A transform replace MUST be validated against payload_schema, and every field not listed in reply_schema.properties MUST equal its input value. A first answer MUST be validated against reply_schema. A reply that fails MUST count as pass, MUST be logged as extension.schema-mismatch and MUST count as a breach. | [hook modes](/pages/api-extension-points/#hook-modes) | (log-line) refuse in observe mode -> pass and one log line. A transform replace that changes a field outside reply_schema -> pass and extension.schema-mismatch. |
| [EXT-020] | A handler MUST get deadline_ms of 5 to 50, 20 by default. A handler that times out, traps or errors MUST count as pass, except at a high-risk veto or transform point whose `on_failure` is `refuse` (SEC-287), where it refuses the plugin-initiated action. Elsewhere a timeout MUST NOT veto. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (log-line) handler of 80 ms at the default -> pass and extension.handler-timeout logged. |
| [EXT-021] | A breach is a timeout, a trap, an error return, a reply over 64 KiB, a replace or answer that fails its schema, a CPU budget overrun, or a skip because the contributor's instance was busy. reply-not-allowed and a chain-cap skip MUST NOT be breaches. The counter is per contributor, point and extension id, and an accepted reply within the deadline MUST reset it to 0. The third consecutive breach MUST stop the extension until the contributor's instance restarts or the user presses Reset. The stop MUST NOT be persisted. The user MUST see a notice and a Reset button. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (log-line) three timeouts -> extension.disabled logged on the next run. Two timeouts, one good call, two timeouts -> still active. Restart the contributor -> active again. |
| [EXT-022] | A run-hook on any point already on the current chain stack, directly or indirectly, MUST fail with extension.reentrant and base code conflict. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (sync-return) handler of A runs B and B's handler runs A -> err conflict, message prefix extension.reentrant. |
| [EXT-023] | A payload, a reply and a chain result MUST each be at most 64 KiB, and an entry at most 16 KiB. A collect point MUST hold at most max_entries (at most 256) and a hook point at most max_handlers (at most 8). | [requestable limits](/pages/reference-errors-and-limits/#requestable-limits) | (sync-return) register entry number max_entries + 1 -> quota-exceeded with extension.cap-exceeded. |
| [EXT-024] | A call to a point that is not declared by an installed and enabled owner MUST fail with extension.unknown-point and base code not-found. | [edge cases and error codes](/pages/api-extension-points/#edge-cases-and-error-codes) | (sync-return) run-hook on "x/y" -> err not-found. |
| [EXT-025] | register and unregister on a point that is not dynamic MUST fail with extension.not-dynamic and base code unsupported. | [dynamic collect points](/pages/api-extension-points/#dynamic-collect-points) | (sync-return) register on a static point -> err unsupported. |
| [EXT-026] | The kernel MUST send the topic ilium.extensions/changed to the owner only, once per point, after any change to the active set (install, uninstall, update, enable, disable, register, unregister, user toggle or reorder, breach stop, Reset, dormant or active change). The payload MUST be {point} with the global point name. Changes within 50 ms MUST merge into one event. No grant is needed. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (event-delivery) a contributor installs -> the owner gets one topic and no one else does. Three registers within 50 ms -> one topic. |
| [EXT-027] | A contribution MUST be dormant when its owner is not installed, is disabled, or does not satisfy its @version. An inactive owner MUST NOT make it dormant. The install MUST NOT fail for a missing owner. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (install-error) install a contributor first -> succeeds, contribution dormant. |
| [EXT-028] | A handler MUST run on the side that owns the call and a contributor MUST declare it on that side. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (install-error) declare a client handler for a server point -> manifest error. |
| [EXT-029] | For veto, transform and first points the owner MUST hold the one action until the chain completes (at most the 100 ms cap plus one deadline) and keep serving other events. For observe points the action MUST NOT wait. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (event-delivery) a veto handler refuses after 30 ms -> the action does not happen. An observe handler of 30 ms -> the action completes first. |
| [EXT-030] | Install MUST NOT fail because a point is full. The active set MUST be the first max_handlers handlers (or max_entries entries) in run order, the rest MUST be dormant with the reason "point full (<n>)", and the owner MUST get ilium.extensions/changed after a recompute. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (event-delivery) 9 contributors on a point with max_handlers 8 -> the last in run order is dormant. |
| [EXT-040] | The core set MUST hold 66 points across 30 core plugins. Hook modes MUST number observe 5, transform 11, veto 10, first 1. | [hook modes at a glance](/pages/reference-core-extension-points/#hook-modes-at-a-glance) | (install-error) run the check tool over the core tables -> counts 66, 30 and 5, 11, 10, 1. |
| [EXT-041] | A point id MUST be <plugin-id>/<point>, where plugin-id is the id of this plugin or the id of a core plugin named in this package's replaces list; such names are accepted only for items listed in that core plugin's surface. | [core extension points](/pages/reference-core-extension-points/#core-extension-points) | (install-error) declare a point "tree" with no plugin id -> manifest error. A foreign prefix outside replaces -> manifest error. |
| [EXT-042] | Every core plugin MUST state whether another plugin may replace it, and its points, services and topics MUST be listed on the core points page. | [summary](/pages/reference-core-extension-points/#summary) | (install-error) run the check tool over the core pages -> every core plugin has a Replaceable value. |
| [EXT-043] | An entry field service MUST name a service with the contributor's own id as prefix that the contributor provides, otherwise the install MUST fail with manifest.extension-entry-invalid. The owner MUST be able to call it without services.use, with the 30 s timeout and 1 MiB caps. | [entry-bound services](/pages/api-extension-points/#entry-bound-services) | (install-error) entry names a service of another plugin -> manifest.extension-entry-invalid. (sync-return) owner calls the entry service with no services.use -> accepted. |
| [EXT-044] | on_failure (pass or refuse) MUST be allowed only on a hook point of risk high and mode veto or transform, final_check (boolean, default false) only on a transform point, and guard (boolean, default false) only on a contributor entry for a point with final_check true and a handler. Otherwise the install MUST fail with manifest.extension-point-invalid. A guard MUST be called once after the transform chain with the final payload, and any refuse MUST end the chain as refused(conflict) extension.vetoed. | [hook modes](/pages/api-extension-points/#hook-modes) | (install-error) on_failure on an observe point -> manifest.extension-point-invalid. (completion) a guard refuses the final payload -> refused(conflict). |
| [EXT-045] | reply_schema MUST be required on transform and first points and MUST be refused (manifest.extension-point-invalid) on observe and veto points. | [hook modes](/pages/api-extension-points/#hook-modes) | (install-error) veto point with reply_schema -> manifest.extension-point-invalid. |
| [EXT-046] | The outermost chain MUST be depth 1. A run-hook from a handler at depth 3 MUST fail with reentrant, base code conflict and message prefix extension.depth-exceeded, MUST count as pass and MUST NOT be a breach. The inner chain MUST run after the handler returns, complete as request-completed at the handler's plugin, and not count toward the outer deadline. | [rules for payloads deadlines ordering and failure](/pages/api-extension-points/#rules-for-payloads-deadlines-ordering-and-failure) | (sync-return) run-hook at depth 3 -> err conflict, prefix extension.depth-exceeded, no breach counted. |
| [EXT-047] | register with a priority above 100 MUST fail with base code invalid-argument and a message prefix extension.schema-mismatch. | [functions](/pages/api-extension-points/#functions) | (sync-return) register priority 101 -> err invalid-argument. |
| [EXT-048] | run-hook above 200 calls per second on one point MUST return rate-limited with retry-after-ms. extension.depth-exceeded, extension.entry-rejected and extension.veto-overridden MUST be logged as listed in the code table. | [edge cases and error codes](/pages/api-extension-points/#edge-cases-and-error-codes) | (sync-return) 201 run-hook calls in one second -> rate-limited. |
| [EXT-049] | An entry's identity MUST be the contribution id (contributes.extensions[].id), given to the owner as ExtensionEntry.extension. Equal ids from two plugins MUST both stay. | [functions](/pages/api-extension-points/#functions) | (event-delivery) two plugins contribute id ocean -> list returns two entries with different contributor. |
| [EXT-050] | A command field in an entry MUST name a command declared by the contributor or one for which it holds commands.invoke, otherwise the install MUST fail with manifest.extension-entry-invalid. An entry that runs a program (worktrees/post-create-steps.command, progress/probe-kinds.command_template) MUST need a matching process.run grant of the contributor (manifest.grant-dependency otherwise). | [core extension points](/pages/reference-core-extension-points/#all-points) | (install-error) entry names ilium.core.fleet/broadcast without commands.invoke -> manifest.extension-entry-invalid. |
| [EXT-051] | A replacement's points item MUST match only with the same kind, the same mode and the same major version, and a services item only with the same method names and major version. Otherwise manifest.replaces-surface-incomplete MUST name the item and the reason. The surface MUST be checked again at each enable and after each Ilium update; an enabled replacement that no longer covers it MUST be turned off, the built-in plugin MUST come back and a notice MUST name the missing items. | [replacing a core plugin](/pages/extending-core-plugins/#replacing-a-core-plugin) | (install-error) replacement point with mode veto for a transform point -> manifest.replaces-surface-incomplete. |
| [EXT-052] | Every core point MUST have a Side (server, client or scene), Version, Deadline, Max and Dynamic value in the core points table. A handler declared on the other side MUST fail the install with manifest.extension-side, a handler MUST get the table's deadline, and register on a point whose Dynamic value is no MUST fail with extension.not-dynamic. | [all points](/pages/reference-core-extension-points/#all-points) | (sync-return) register on ilium.core.smart-copy/recognisers -> ok. Register on ilium.core.tree/node-sorts -> err unsupported. |
| [EXT-053] | Several installed packages MAY replace one core plugin, and at most one MUST be enabled. Enabling another MUST ask the user and turn the previous replacement off. A replaces list with its own id or an id twice MUST fail with manifest.replaces-cycle, and more than 4 ids with manifest.schema. | [replacing a core plugin](/pages/extending-core-plugins/#replacing-a-core-plugin) | (event-delivery) enable replacement B while A is enabled -> prompt, then A is off. |
| [EXT-054] | Records written by a log-sinks handler during its call, and the host's extension.* records about log-sinks handlers, MUST NOT be delivered to log-sinks. Records MUST be batched: one chain per 250 ms with up to 64 records. | [diagnostics](/pages/core-plugin-diagnostics/#extension-points) | (event-delivery) a log-sinks handler logs at warn -> no new chain starts from it. |
| [EXT-055] | The chain on ilium.core.terminal/before-send-input MUST NOT run for keystrokes typed into a pane. It MUST run once per write that Ilium makes on someone's behalf (paste, dialog, broadcast, voice, plugin write-input). | [terminal](/pages/core-plugin-terminal/#extension-points) | (event-delivery) type 10 keys -> no chain. Paste once -> one chain with source paste. |
| [EXT-056] | A snapshot reply over max_bytes MUST be dropped, logged snapshot.section-too-large and not stored. restore MUST be called after before-restore completes and before panes respawn, with 2 s per call. | [sessions](/pages/core-plugin-sessions/#extension-points) | (event-delivery) a section replies max_bytes + 1 -> not stored, log line present. |
