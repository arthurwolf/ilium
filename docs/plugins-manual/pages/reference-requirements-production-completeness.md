## Requirements for production completeness

This page lists every requirement of the production pages added to close the gaps found by the production-completeness audit (grant expiry, refusals and changes, audit of grant events, unattended grants, helper and server death, out-of-band kill, resource limits, registry shutdown, user reports, air-gapped transfer, configuration export, compliance and audit collection, bad-release response, text direction and input, colour and no-colour, non-text panes, language coverage, API change proposals, CI report formats, conformance claims, test strategy and SDK pinning). The statement is the owner bullet word for word. Change the bullet first, then copy it here.

| Id | Statement | Page | Testable how |
|---|---|---|---|
| PDX-001 | A plugin project MUST commit its lockfile (`Cargo.lock` for Rust, `bun.lock` for TypeScript), and a release build or `ilium plugin check --release` without one MUST fail with `build.unpinned-inputs` as defined by [DEV-893]. | [guide-pinning-the-sdk](/pages/guide-pinning-the-sdk/) | Delete Cargo.lock from a Rust template project and run `ilium plugin check --release`: the exit code is non-zero and the output contains `build.unpinned-inputs`. |
