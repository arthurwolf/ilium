## Requirements for developer tooling

This page lists every requirement with the prefix DEV. Each row gives the id, the statement, the page that defines it and a way to test it. The tests for the plugin command line, the check and lint rules, the project templates, the test harness, the conformance suite, the debugging tools and the CI and documentation guides are written from this table.

Words: MUST and MUST NOT are required. SHOULD is expected unless a reason is recorded. MAY is allowed. An id is never reused. The statement here is the same text as on the page. If the two differ, the page wins and this table has a defect.

## You will need

- The pages named in the "Page" column. Each id appears there as `[DEV-nnn]` at the start of a bullet.
- A scratch project made with `ilium plugin new`. See [Project templates](/pages/reference-project-templates/).

## How to read the table

- The id ranges are fixed by area. See the area headings below.
- "Testable how" says what a test does. It is a method, not a test case.
- Rows are grouped by area and sorted by id.


## CLI conventions

| DEV-002 | A command that builds MUST detect the language from the project files. A `Cargo.toml` means Rust. A `package.json` means TypeScript. A command MUST NOT start a session itself. | [reference-plugin-cli](/pages/reference-plugin-cli/) | Run the command and assert the exit code and the error code |
| DEV-005 | The commands in the offline column of the table below MUST work with no running session, no network and no home-directory configuration beyond the trust store. | [reference-plugin-cli](/pages/reference-plugin-cli/) | Run the command in a scratch project and assert the output and exit code |

| DEV-007 | Every command MUST exit with one of the codes below, and the `exit_code` field of its `result` record MUST equal the process exit code. | [reference-plugin-cli](/pages/reference-plugin-cli/) | Run the command and assert the exit code and the error code |

| DEV-026 | A command listed as JSONL in the table below MUST print JSONL always. `--json` on such a command MUST be accepted and have no effect. | [reference-plugin-cli](/pages/reference-plugin-cli/) | Run with --json and assert the records and their field order |

| DEV-028 | Text output MUST be stable enough to read but is not a contract. Scripts MUST use `--json`. | [reference-plugin-cli](/pages/reference-plugin-cli/) | Run with --json and assert the records and their field order |
| DEV-029 | A flag MUST override the environment variable that has the same effect. | [reference-plugin-cli](/pages/reference-plugin-cli/) | Run the command in a scratch project and assert the output and exit code |

The code `D27` (registry publishing) governs `publish`, and the codes of the restart rule and of the limits table govern the harness and the conformance cases. A requirement that conflicts with a decision is a defect in the requirement.
