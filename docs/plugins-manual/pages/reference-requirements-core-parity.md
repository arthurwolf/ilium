## Core parity requirements

These requirements say that the core plugins keep every feature of Ilium. Each row has an id, a MUST statement, the page that explains it and a test. The ids use the prefix COR. They follow the style of [requirements](/pages/reference-requirements/).

Related pages: [feature traceability](/pages/reference-feature-traceability/), [kernel and boot](/pages/reference-kernel-and-boot/), [config and data migration](/pages/reference-config-and-data-migration/), [CLI compatibility](/pages/reference-cli-compatibility/), [roadmap](/pages/roadmap/).

| Id | Statement | Page where explained | Testable how |
|---|---|---|---|
| [COR-001] | Every feature F-001 to F-116 MUST behave as in the baseline when its owner is enabled. | [Feature traceability](/pages/reference-feature-traceability/) | Run the baseline user-doc scenario for each row against the plugin build and compare the observable result. |
| [COR-002] | Every feature MUST have one primary owner, the first one named in its Owner cell. | [Feature traceability](/pages/reference-feature-traceability/) | Script: count rows per id in the table; the count is 116 and each owner cell is non-empty. The duplicates section lists no open claim. |
| [COR-003] | A row of the traceability table with Kind `native-kernel` MUST name `kernel` first in its Owner cell, and every config table named in its Config keys column MUST appear in the key-by-key table of the migration page. | [Feature traceability](/pages/reference-feature-traceability/) | Script: parse the table; check the Owner prefix of each `native-kernel` row; check each named table against the key-by-key table. |
| [COR-010] | Kernel parts MUST stay in the kernel and MUST work with `--no-plugins`: PTY and vt100, tree model, IPC, snapshot writer, config store, keymap, layout, look painter, scene host, plugin host, recovery page, HTTP listener, kernel CLI. | [Kernel and boot](/pages/reference-kernel-and-boot/) | Start with `--no-plugins`; attach, create a pane, type, split, detach, reattach and open the recovery page. |
| [COR-011] | Every plugin-owned feature MUST keep its settings, keys, CLI output, data files and defaults. | [Feature traceability](/pages/reference-feature-traceability/) | For each plugin, diff the Behaviour contract table against the plugin build: settings rows, key actions, config keys, CLI records and data paths. The diff must be empty. |
| [COR-020] | The server MUST restore the snapshot before any plugin is instantiated, activate `startup` plugins in dependency order and bind the client socket last. | [Kernel and boot](/pages/reference-kernel-and-boot/) | Spy plugin with `startup` records the tree at `activate`; it sees the restored tree. |
| [COR-021] | Exactly the core plugins marked `startup` MUST be active at boot; the others MUST stay inactive until their trigger fires. | [Kernel and boot](/pages/reference-kernel-and-boot/) | Boot with no client; list active plugin sides; compare with the activation table. |
| [COR-022] | Disabling a core plugin MUST have the stated effect, MUST NOT delete its data and MUST leave the recovery page working. | [Kernel and boot](/pages/reference-kernel-and-boot/) | For each of the 26 plugins that can be disabled (all except the four essential ones, see [Which core plugins can be disabled](/pages/core-plugins/#which-core-plugins-can-be-disabled)): disable it, check the table row, check stored data, open recovery. For the four essential plugins assert that no disable switch is offered. |
| [COR-023] | The scene world MUST NOT import `extensions`, and `capabilities.scene` MUST NOT hold extension grants. | [Kernel and boot](/pages/reference-kernel-and-boot/) | Manifest with `extensions.contribute` under `capabilities.scene` fails with `manifest.grant-side`. |
| [COR-024] | Each change in the live reload and restart table MUST apply as stated. | [Kernel and boot](/pages/reference-kernel-and-boot/) | Change one value of each kind with a client attached; check whether the running side sees it without a restart. |
| [COR-030] | A kernel tab MUST have at most one holder of `settings.write-kernel:<tab>`. | [Config and data migration](/pages/reference-config-and-data-migration/) | Install two T1 fixtures asking for the same tab; the second fails with `manifest.settings-owner`. |
| [COR-031] | `settings.write-kernel:<tab>` MUST be T1 only and high risk; `settings.read-kernel:<tab>` MUST be open to every tier. | [Config and data migration](/pages/reference-config-and-data-migration/) | T2 with the write grant fails with `manifest.grant-tier`; T3 with the read grant installs. |
| [COR-032] | Plugin state in a snapshot MUST use `snapshot-sections` with a `schema_version`; a section over its `max_bytes` (at most 256 KiB) MUST be dropped without losing the previous value; a failed plugin MUST NOT block the snapshot. | [Config and data migration](/pages/reference-config-and-data-migration/) | Write a 300 KiB section; the previous value survives and the snapshot is written. |
| [COR-033] | The plugin build MUST NOT rename or move any key in `config.toml` or `.ilium/config.yaml` and MUST keep unknown keys. | [Config and data migration](/pages/reference-config-and-data-migration/) | Run the build on a config with an unknown key, change one setting, diff the files; only that setting differs. |
| [COR-034] | A write through `settings.write-kernel:<tab>` that names a key outside the tab's "Keys written" column MUST fail with `settings.key-not-owned` and write nothing. | [Config and data migration](/pages/reference-config-and-data-migration/) | Write a key owned by another tab of the same table; assert `settings.key-not-owned` and an unchanged file. |
| [COR-090] | A `config.toml` or `.ilium/config.yaml` that cannot be parsed MUST be left unchanged on disk and MUST NOT be rewritten while it stays unparseable. The host MUST use the built-in defaults for that file for the run, MUST print one `warning` with the code `config.parse-error` that names the file, and MUST still boot. | [Config and data migration](/pages/reference-config-and-data-migration/) | Start a server with `config.toml` holding `[ui`; assert the bytes are unchanged, the warning, and a running server. |
| [COR-040] | A plugin MUST declare every `ilium` subcommand it owns; no built-in command without a declared owner MUST NOT remain. | [CLI compatibility](/pages/reference-cli-compatibility/) | Compare `ilium --help` with the ownership table; every non-kernel command names a plugin. |
| [COR-041] | Arguments, options, defaults, output records and exit codes of every command MUST equal the baseline CLI reference. | [CLI compatibility](/pages/reference-cli-compatibility/) | Replay the examples of `src/docs/cli-reference.md` (a file of the repository user documentation, outside this manual) and compare the JSONL records and exit codes. |
| [COR-042] | A disabled or failed owner MUST give exit code 1 and a record with `cli.owner-disabled` or `cli.owner-failed` that names the plugin. | [CLI compatibility](/pages/reference-cli-compatibility/) | Disable chatroom; run `ilium chat tail`; check record, plugin id and exit code 1. |
| [COR-043] | Every manifest and sample on a core-plugin page MUST pass `ilium plugin check` with the `ilium:plugin@0.1.0` rules. | [Core plugins](/pages/core-plugins/) | Extract the Complete manifest block of each of the 30 pages and run the check; zero errors. |
| [COR-050] | Each of the 30 core-plugin pages MUST hold a Complete manifest section whose sides, worlds, grants and contributions match its tables; the core-plugins index MUST state 30. | [Core plugins](/pages/core-plugins/) | Script: parse each manifest; compare sides and grants with the page tables; compare the index count with the page count; every number of pages stated in `core-plugins.md` equals the count of `core-plugin-*.md` files; every `cli` key in a page's Manifest fragment appears with the same value in its Complete manifest. |
| [COR-060] | The roadmap MUST give each wave a gate test. | [Roadmap](/pages/roadmap/) | Every wave row has a non-empty gate column that names a test. |
| [COR-061] | The roadmap MUST state what stays native in each wave. | [Roadmap](/pages/roadmap/) | Every wave row has a non-empty native column. |
| [COR-080] | Captured microphone audio MUST stay in memory and MUST NOT be written to disk, a log or a crash report; the buffer MUST be released when the transcription job ends, fails or is cancelled. | [Voice](/pages/core-plugin-voice/#data-and-privacy) | Record, release the key, cancel, fail the job; assert no file under the plugin data and log directories holds audio and the buffer length is 0 after each. |
| [COR-081] | Audio MUST be sent off the machine only when the configured transcription provider is remote, and the voice strip MUST show a "remote" marker while it is. With a local provider the plugin MUST open no network connection. | [Voice](/pages/core-plugin-voice/#data-and-privacy), [Plugin privacy](/pages/user-privacy/#core-plugins-and-ai-providers) | Local provider in a network namespace without interfaces: success, zero connections. Remote provider: one connection to the configured host and the marker is shown. |
| [COR-082] | The plugin SHOULD name the provider and whether it is local or remote in Settings before the first capture, and MUST NOT switch from a local to a remote provider without the user's change. | [Voice](/pages/core-plugin-voice/#data-and-privacy) | Fresh install: settings row shows provider and locality; a provider that fails never falls back to a remote one. |
| [COR-083] | A transcript MUST be kept only in memory for the current voice session, MUST NOT be written to the log at Info level or above, and MUST be dropped when the session ends. | [Voice](/pages/core-plugin-voice/#data-and-privacy) | Speak a phrase, end the session; scan logs and storage for the phrase; none; the session transcript is empty. |
| [COR-084] | Audio and transcripts MUST NOT be published on a topic, sent in an event payload or exposed to another plugin; only the command id the transcript maps to MAY leave the plugin. | [Voice](/pages/core-plugin-voice/#data-and-privacy) | Subscribe a fixture plugin to every topic and event during a session; assert no payload holds the audio bytes or the transcript text. |
