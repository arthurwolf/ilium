## Requirements: kernel and host

This page lists every normative statement of the kernel and host lane. Each statement has a stable id `HST-NNN`, appears under the same id in the page named in the third column, and has a test method in the fourth. A test author cites the id in the test name. Ids are not dense: the blocks are HST-001 to 045 (architecture), 050 to 089 (runtime), 100 to 125 (IPC), 150 to 171 (helper), 180 to 216 (scheduling), 250 to 272 (rendering), 300 to 313 (budgets), 350 to 363 (telemetry), 380 to 388 (platform), 400 to 412 (errors and limits, owned by [Error codes and limits](/pages/reference-errors-and-limits/)), 450 to 457 (agent signatures), 470 to 478 (extension points and menu provider) and 490 to 494 (intents and tree). Unused numbers are reserved and have no requirement. If a statement and its page differ, the page wins and this table is regenerated.

## Words and ids

- **MUST** and **MUST NOT** are absolute. **SHOULD** and **SHOULD NOT** allow a stated exception. **MAY** is optional.
- Ids are fixed once published. A removed requirement keeps its id and is marked withdrawn. An id is never reused.
- Ranges: 001-049 host architecture and crates; 050-099 runtime and Wasmtime; 100-149 IPC; 150-179 sandbox helper; 180-249 scheduling, deadlines, cancellation and backpressure; 250-299 rendering; 300-349 budgets and benchmarks; 350-379 telemetry; 380-399 platform support; 400-449 limits and the restart rule; 450-469 detection loop; 470-489 hooks and providers across sides; 490-499 client-side tree and intent semantics.
- Test methods: unit tests in `ilium-plugin-host`, integration tests that start a host and plugin fixtures, conformance fixtures, IPC round-trip tests in `ilium-ipc`, benchmarks B1 to B24 with the thresholds of [Performance budgets and benchmarks](/pages/reference-host-budgets/), platform CI lanes, and manual checks.
