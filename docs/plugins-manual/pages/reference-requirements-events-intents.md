## Requirements for events and intents

Normative behaviour of event delivery, ordering, payloads, intents, the input journal and prompt events.

The rows follow the format and the observation channels of the [requirements index](/pages/reference-requirements/). The id prefix is `EVT`.

| Id | Requirement | Source | Observable test |
|---|---|---|---|
| [EVT-001] | The host MUST deliver events to on-events in batches, in the order they happened, one call at a time per plugin side. | [how events are delivered](/pages/reference-events-and-intents/#how-events-are-delivered) | (event-delivery) emit three events in order -> one batch holds them in that order. |
| [EVT-002] | A plugin MUST receive only events for which it holds the grant and has subscribed. | [event catalogue](/pages/reference-events-and-intents/#event-catalogue) | (event-delivery) subscribe without panes.read -> no pane events arrive. |
| [EVT-003] | An on-events call MUST finish within its deadline. A breach MUST trap and count as one failure. | [traps](/pages/reference-errors-and-limits/#traps) | (trap) block 100 ms in on-events -> trap. |
| [EVT-004] | A full event queue MUST admit a drop-oldest event by evicting the oldest queued drop-oldest event of any kind, count it, and put an events-dropped event at the start of the next batch. When the queue is full, no drop-oldest event is pending and a never-dropped event arrives, the host MUST restart the instance as a failure, and the new instance MUST receive tree-changed for every node. | [how events are delivered](/pages/reference-events-and-intents/#how-events-are-delivered) | (event-delivery) overflow the queue with output matches -> events-dropped with a count appears first in the next batch. |
| [EVT-005] | pane-lifecycle-changed MUST carry pane, state and by, and MUST never be dropped. | [events](/pages/api-pane-lifecycle/#events) | (event-delivery) freeze a pane -> one event with state frozen and by set. |
| [EVT-006] | ui-action events MUST carry the widget key and an action value of the kind documented for that widget. | [ui action kinds and action values](/pages/reference-events-and-intents/#ui-action-kinds-and-action-values) | (event-delivery) click a button with key "save" -> ui-action with key "save". |
| [EVT-010] | Every intent MUST be submitted as a submission in a return list of on-events. Intents MUST NOT be callable as functions. | [submissions and outcomes](/pages/reference-events-and-intents/#submissions-and-outcomes) | (completion) return a send-input submission -> one request-result for it. |
| [EVT-011] | An intent whose shape is malformed MUST be the batch-level offender (the lowest index) and complete as refused(invalid-argument); every other submission of the batch MUST complete as refused(cancelled). An intent with a well-formed but invalid value MUST complete as refused(invalid-argument) alone. | [intent table](/pages/reference-events-and-intents/#intent-table) | (completion) submit freeze-pane with a text node id -> refused(invalid-argument). |
| [EVT-012] | An intent that needs a grant the plugin lacks MUST be a batch-level offender when no shape offender has a lower index, and MUST complete as refused(not-permitted); every other submission of the batch MUST complete as refused(cancelled). | [intent table](/pages/reference-events-and-intents/#intent-table) | (completion) submit freeze-pane without panes.lifecycle -> refused(not-permitted). |
| [EVT-013] | An intent for a node that no longer exists MUST complete as failed(not-found) or refused(not-found) as the table states. | [intent table](/pages/reference-events-and-intents/#intent-table) | (completion) submit a pane intent for a removed node -> not-found. |
| [EVT-014] | The WIT outcome variant MUST contain ok, ok-node, duplicate, refused, failed, cancelled and ok-epoch. | [submissions and outcomes](/pages/reference-events-and-intents/#submissions-and-outcomes) | (sync-return) build the WIT with the check tool -> the seven cases exist. |
| [EVT-020] | send-input MUST be refused with pane-not-ready for a restored pane whose process has not started. | [pane states after a restore](/pages/api-panes/#pane-states-after-a-restore) | (completion) send-input to a restored pane -> refused(pane-not-ready). |
| [EVT-021] | send-input and agent-action MUST carry a dedup key. A submission of either kind with no key MUST be a shape offender: it completes as refused(invalid-argument) and the other submissions complete as refused(cancelled). | [duplicate submissions and dedup keys](/pages/requests-and-outcomes/#duplicate-submissions-and-dedup-keys) | (completion) submit send-input with no dedup key -> every submission completes refused. |
| [EVT-022] | send-input with journal true MUST write the journal entry before the keys reach the pane. | [uncertain input after a restart](/pages/requests-and-outcomes/#uncertain-input-after-a-restart) | (log-line) restart the server between journal write and outcome -> input-uncertain on activation, no replay. |
| [EVT-030] | The settings-changed event MUST carry the changed keys and their new values, delivered once per debounce window. | [extended payloads of existing events](/pages/api-events/#extended-payloads-of-existing-events) | (event-delivery) change two values inside the window -> one event with both keys. |
| [EVT-031] | cli-cancelled MUST be a distinct event from a cli exit with a signal. | [extended events](/pages/reference-events-and-intents/#extended-events) | (cli-exit) cancel a CLI call -> cli-cancelled and exit code per the CLI page. |
| [EVT-040] | A prompt sent by a plugin, a schedule or voice MUST fire input-submitted only, and not a user-typed prompt event. | [event catalogue](/pages/reference-events-and-intents/#event-catalogue) | (event-delivery) a plugin sends a prompt -> input-submitted only. |
| [EVT-041] | A plugin MUST NOT see tree-changed for a node after its node-removed. The host MUST remove the node from pending tree-changed lists and discard pending coalesced events keyed by that node when node-removed is queued. | [event catalogue](/pages/reference-events-and-intents/#event-catalogue) | (event-delivery) remove a node with a pending tree-changed -> no tree-changed after node-removed. |
| [EVT-042] | Events about the plugin own actions MUST be delivered unless the table marks them as suppressed. | [event catalogue](/pages/reference-events-and-intents/#event-catalogue) | (event-delivery) set a title as a plugin -> title-changed arrives as documented. |
| [EVT-043] | A coalesced event MUST always merge with the pending event of the same kind and key, whatever the queue fill, and keep the newest payload at the position of the newest occurrence. | [how events are delivered](/pages/reference-events-and-intents/#how-events-are-delivered) | (event-delivery) send 2,000 screen-changed for one pane -> one queued event with the newest revision. |
| [EVT-044] | agent-activity-changed MUST be a never-dropped event. | [how events are delivered](/pages/reference-events-and-intents/#how-events-are-delivered) | (event-delivery) send 1,500 agent-activity-changed to a queue of 1,024 -> none dropped and the instance is restarted when it cannot fit. |
| [EVT-045] | events-dropped MUST be coalesced by (event, source), MUST never be dropped, and MUST sit at the head of the next batch. | [how events are delivered](/pages/reference-events-and-intents/#how-events-are-delivered) | (event-delivery) drop output-matched twice -> one events-dropped with one record whose count adds up. |
| [EVT-046] | The event_queue ceiling MUST be 4,096 for T1 and 1,024 for T2 and T3; a larger request MUST be clamped and logged. | [how events are delivered](/pages/reference-events-and-intents/#how-events-are-delivered) | (log-line) ask for 4,096 as T2 -> effective 1,024 and one clamp line. |
| [EVT-047] | After every activation of a plugin that holds tree.read, the first batch MUST start with exactly one tree-changed event listing every node in pre-order. Without tree.read nothing MUST be sent. | [how events are delivered](/pages/reference-events-and-intents/#how-events-are-delivered) | (event-delivery) activate with 3 nodes -> one event with 3 ids. |
| [EVT-048] | Events produced while a plugin activates MUST be queued and delivered after activate returns ok, and MUST be discarded without an events-dropped report if activate fails or breaches its deadline. | [how events are delivered](/pages/reference-events-and-intents/#how-events-are-delivered) | (event-delivery) emit events during a failing activate -> no events-dropped on the next activation. |
| [EVT-049] | Pending tree-changed events MUST merge into one event whose list is the union of the node ids, in tree pre-order without duplicates. | [event catalogue](/pages/reference-events-and-intents/#event-catalogue) | (event-delivery) change nodes 5 and 3 in separate events -> one event [3, 5]. |
| [EVT-050] | A refused send-input attempt MUST NOT take a rate token. | [send-input](/pages/api-intent-send-input/) | (completion) refuse 25 send-input for pane-not-ready, then one valid -> accepted. |
