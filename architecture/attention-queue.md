## Attention queue

`ilium-client/src/attention/` holds a pure core with no I/O: `item` (kinds Question > Stuck > WaitingOn > Changed, evidence fingerprint, generation), `queue` (ordering, merge, stale/generation rejection, persistence validation), `instant` (deterministic items from `AgentState`), `parse` (lenient parsing of the optional `attention` list), `refresh` (coalescing gate), `turbo` (AIMD concurrency limiter and per-pane scheduler) and `settings`. The queue is client-side and global across projects; the server and IPC protocol are unchanged. Visit memory lives in `queue`: `mark_looked` records the fingerprint and kind seen (`VisitedAs`, persisted with `#[serde(default)]`); `next_to_visit` skips handled agents (visited, not more urgent, and either unchanged or inside the 5 minute `REVISIT_COOLDOWN_MS`) and falls back to the longest-ago visit, so a press walks the whole queue before repeating; `ordered_for_display` puts handled agents last in the panel and overview.

Shared mode adds an `attention` key to the Sort reply. `restructure.rs` strips it from the raw JSON before the strict `LlmRestructurePlan` parse (which denies unknown fields), so a bad list never fails the sort and never enters the IPC `RecommendedRestructurePlan`. Turbo mode makes separate per-agent calls under its own limiter, independent of the naming workers' limiter. Instant items are never removed by the model, replies carry the fingerprint they analysed and are dropped per pane when it moved, and agents with unchanged fingerprints are always skipped.

The briefing box is `attention/briefing.rs` (pure: sections, the single row-count function `reserved_rows`, rendering, hit rectangles and the per-pane `BriefingState` lifecycle) plus `app_attention_briefing.rs` (the `App` glue). `AttentionItem` carries an additive `Briefing` (`status_summary`, `why_here`, `suggested_action`, `from_llm`; serde defaults keep old stores loading); the model fills it through both prompts, `instant::fallback_briefing` supplies the labelled automatic wording, and `queue::merge_briefing` keeps AI and automatic text from mixing. `PaneViewport` gains a `briefing_area` and `briefing_bottom_rule` reserved right after the last-prompt banner by `with_briefing_reserved`; `App::pane_viewports` and `ui.rs` both read `briefing_rows`/`briefing_view`, so the PTY size and the drawn box cannot disagree. A visit is recorded in `open_attention_pane` (press and panel) or detected at the next reconcile as a focused pane looked at since the last pass (overview jump); the entry snapshots the item because a finished agent's item disappears once read. State is per client run and not persisted. The `show_briefing` setting (on by default, effective unless the mode is Off) flows through config, the Attention settings tab and `attention.show_briefing` in the control API.
