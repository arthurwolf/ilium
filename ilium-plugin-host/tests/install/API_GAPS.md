# API gaps of the install-deps lane, part 1 (PKG-260 .. PKG-348)

Items the tests use that the skeleton does not have. Each bullet: crate, signature, ids, why.

- ilium-plugin-host `cli::CliEnv` extra fields: `cache_dir: PathBuf, platform: ilium_plugin_api::Platform, host_release: String, env: BTreeMap<String, String>, system_dir: Option<PathBuf>` (PKG-260, 267, 268, 273, 297, 325, 346): the CLI needs the cache folder, the platform gate, the running release, the environment and an admin plugin root as inputs to be testable.
- ilium-plugin-host `registry_client`: `Fetcher::get_response(&self, url: &str) -> Result<FetchResponse, FetchError>` and `struct FetchResponse { status: u16, location: Option<String>, content_type: Option<String>, content_length: Option<u64>, body: Vec<u8> }` (PKG-260, 261): redirects, declared size and content type are invisible through `get`.
- ilium-plugin-host `testing::FakeRegistry`: `new(base_url: &str) -> Self`, `publish(&mut self, package: Vec<u8>, channel: &str)`, `try_publish(&mut self, package: Vec<u8>, channel: &str) -> Result<(), Diagnostic>`, `documents(&self) -> Vec<(String, Vec<u8>)>` (PKG-263, 313): serves index and package documents to a `FakeFetcher`.
- ilium-plugin-host `install`: `struct InstallOptions { allow_unsigned: bool, .. } + Default`, `Installer::with_options(PackageStore, state_dir: PathBuf, InstallOptions) -> Installer` (PKG-269..299): the installer needs the state dir (grants) and the unsigned switch.
- ilium-plugin-host `install::InstallStep { Acquire, Fetch, Validate, Review, Stage, Commit, Notify }` and `Installer::install_crashing_after(&self, package: &[u8], consent: &dyn Consent, step: InstallStep) -> Result<(), Diagnostic>` (PKG-269, 271, 272): crash-injection after a given step.
- ilium-plugin-host `Installer::recover_at_start(&self) -> Result<RecoveryReport, HostError>` with `RecoveryReport { removed_staging: Vec<PathBuf> }` (PKG-269, 271): orphan staging cleanup.
- ilium-plugin-host `Installer::instantiated_count(&self) -> usize` (PKG-272): proves the installer never instantiates a component.
- ilium-plugin-host `install::FirstActivate { Ok, Error, Trap, DeadlineMissed }`, `Installer::finish_update(&self, plugin: &PluginId, first: FirstActivate) -> Result<UpdateOutcome, Diagnostic>`, `UpdateOutcome::Committed { version: String, deactivation_reason: String } | RolledBack { restored_version, skipped_version, log_code: String, counted_in_failure_window: bool }` (PKG-278, 284, 285, 286): the swap and its trial.
- ilium-plugin-host `Installer::uninstall(&self, plugin: &PluginId, purge: bool) -> Result<_, Diagnostic>` and `check(&self, package: &[u8], CheckMode) -> CheckReport { diagnostics: Vec<Diagnostic>, last_stage: u8 }` (PKG-273, 294): skeleton signatures differ.
- ilium-plugin-host `signing`: `TrustStore::default_path(env: &BTreeMap<String, String>, home: &Path) -> PathBuf`, `TrustStore::save_atomic(&self, path: &Path) -> io::Result<()>` (mode 0600), `SigningKey::from_seed(seed: [u8; 32]) -> SigningKey`, `SigningKey::key_id(&self) -> String` (PKG-267, 283).
- ilium-plugin-host `registry`: `downloads_dir(cache: &Path) -> PathBuf`, `registry_cache_dir(cache: &Path, url: &str) -> PathBuf` (PKG-267).
- ilium-plugin-host `engine::compile_cache_key(component_sha256: &str, engine_id: &str) -> String` (PKG-268).
- ilium-plugin-host `storage::write_bucket_stamp(storage_root: &Path, plugin: &str, data_version: u64) -> io::Result<()>` (PKG-288): sets the data version the plugin's storage was last written with.
- ilium-plugin-host `autoupdate` module (PKG-300..305): `AutoUpdateMode { Off, Notify, Install }`; `AutoUpdateConfig { mode, os_metered: bool, .. }` with `from_toml(&str) -> Result<_, Diagnostic>` (interval 1..=168) and `with_policy(self, Option<AutoUpdateMode>) -> Self`; `schedule(&AutoUpdateConfig) -> Schedule { at_start: bool, interval: Duration, max_jitter: Duration }`; `should_check_network(&AutoUpdateConfig) -> bool`; `decide(&AutoUpdateConfig, &UpdateCandidate) -> AutoAction { Install, Notice(Notice) }`; `Notice { plugin, old_version, new_version, new_grants, changelog_url, actions: Vec<NoticeAction> }`; `NoticeAction { Update, Later, SkipThisVersion }`; `later_hides_for() -> Duration`; `UpdateCandidate { plugin, old_version, new_version, new_grants, adds_replaces, key_changed, channel_selected, changelog_url }`.
- ilium-plugin-host `resolve` (PKG-310..348): `PluginVersion::parse(&str) -> Result<_, Diagnostic>` (`manifest.version-invalid`, `Ord`, build metadata ignored); `VersionRange::parse(&str) -> Result<_, Diagnostic>` (`manifest.requires-invalid`) with `matches(&self, &PluginVersion, allow_prerelease: bool) -> bool`; `parse_service_requirement(&str) -> Result<ServiceRequirement { interface, range }, Diagnostic>`; `parse_point_reference(&str) -> Result<PointReference { plugin, point, range }, Diagnostic>`; `resolve_plan(&ResolveInput) -> Result<ResolvedPlan, Vec<Diagnostic>>` with `ResolveInput { incoming, installed: Vec<PlanPackage>, sources: Vec<SourcePackage>, channel, host_release, is_update, pins: Vec<String> }`, `PlanPackage { id, version, needs: Vec<(String, String, bool)>, host: Option<String> }`, `SourcePackage { package, sha256, yanked, channel, source_rank }` (Clone), `ResolvedPlan { steps: Vec<PlanStep { action: PlanAction, id, version }> }` + `chosen_source_sha(&self, id: &str) -> Option<String>`, `PlanAction { Install, Update, Keep }` (Debug, PartialEq).
- ilium-plugin-api: confirm `generated::types::PluginId` is public at that path and `manifest::CheckMode` has an `Install` variant (PKG-273).
- Manual conflict, not an API gap: unsigned install code is `trust.unsigned` (PKG-229) or `install.unsigned` (DEV-143); PKG-262 accepts either.

# Part 2 (PKG-350 .. PKG-360, PKG-654)

- ilium-plugin-host `lifecycle`: `struct StartNode { id: String, tier: u8, requires_plugins: Vec<String>, requires_service_providers: Vec<String> }` (Clone), `fn start_order(nodes: &[StartNode]) -> Result<Vec<String>, Vec<Diagnostic>>` (Kahn, smallest (tier, id byte order) first), `fn shutdown_order(nodes: &[StartNode]) -> Result<Vec<String>, Vec<Diagnostic>>` (exact reverse), `pub const MAX_CONCURRENT_ACTIVATIONS: usize = 4` (PKG-350, 351): pure ordering functions for the activation order.
- ilium-plugin-host `cli::CliEnv` extra field `policy_file: Option<PathBuf>` (PKG-357): path of the system policy TOML used by the CLI.
- Assumptions to confirm: the user config is `<config_dir>/config.toml` with `[plugins] channel` (PKG-354, 356); `ilium plugin lock` writes `plugins.lock` into the cwd (PKG-359); a policy refusal exits 7 with a `policy.*` code (PKG-357).
- Manual conflict, not an API gap: PKG-359 names the lock file `plugins.lock`, PKG-428 names it `ilium-plugins.lock`; these tests follow PKG-359.
- Manual gaps: the manifest `contributes.services.provides` JSON shape in `service_plugin` follows reference-manifest.md; a minimal `{}` schema file is assumed acceptable (PKG-654).
