# API gaps: registry (registry protocol and distribution commands) tests

Lane registry-publish, part 1 (PKG-361..PKG-445). Everything below is missing from the skeleton or unspecified in the manual. The tests compile against the skeleton except for items 1 to 3.

- ilium-plugin-host dev-dependencies: `ed25519-dalek`, `sha2`, `base64` (and `serde_json`, `tempfile`, `toml`, `proptest` already present). Needed by `common.rs` to sign registry metadata (PKG-362, 364, 419) and fixture packages. Without them `common.rs` does not compile.
- ilium-plugin-host `package::write_package` and `signing::sign` must work (skeleton `unimplemented!`); `common.rs` calls `write_package` to build the fixture packages of PKG-363, 375, 426, 429.
- ilium-plugin-host `registry_client::Fetcher::put(&self, url: &str, headers: &[(String, String)], body: &[u8]) -> Result<HttpResponse, FetchError>` with `HttpResponse{status: u16, headers: Vec<(String, String)>, body: Vec<u8>}`; PKG-392, 393, 395, 396, 441..443. Why: `get` cannot carry the publish upload, the token header, yank or deprecate. The FakeNet in `common.rs` must then override `put` and log it, so `requests_to("/publish/...")` sees uploads (tests pkg_392_*, pkg_441_*, pkg_443_* assume this).
- ilium-plugin-host `registry_client::Fetcher::get_with(&self, request: &HttpRequest) -> Result<HttpResponse, FetchError>` with `HttpRequest{url, headers}`; PKG-372 (ETag, If-None-Match, 304, redirects), PKG-374 (proxy), PKG-375 (Range resume), PKG-376 (User-Agent only). Why: `get` returns bytes only; headers, status 304 and redirect hops are unobservable. Covered meanwhile by doc_ tests.
- ilium-plugin-host `registry_client::Fetcher::wait(&self, delay: Duration)` (or an injected clock) and `FetchError::{Timeout(TimeoutKind), TooManyRedirects, TooLarge}`; PKG-369, 372, 373. Why: the 1 s, 2 s, 4 s retry waits and the 10/30/120/600 s timeouts need an injectable clock to be tested without sleeping. pkg_373_* only count attempts (3 or 4).
- ilium-plugin-host `registry_client::{confusable_skeleton(&str) -> String, is_reserved_prefix(&str) -> bool, namespace_owns(publisher_id: &str, plugin_id: &str) -> bool}`; PKG-387, 388, 389. Why: the five skeleton vectors (`r-n.tool` to `mtooi`, `corn` to `com`) and the reserved-prefix check are server rules; the client tests reach them only through `publish` against a fake server.
- ilium-plugin-host `registry_client::check_validity_windows(timestamp_secs: u64, snapshot_secs: u64, root_secs: u64) -> Vec<Diagnostic>`; PKG-367 (WARN). Why: the 1 day, 7 day and 1 year issue windows are an operator rule with no client observable.
- ilium-plugin-host `registry_client::{PublishPolicy, review_level(&Manifest, first_publish: bool) -> ReviewLevel, rate_limit_ok(publishes_in_hour: u32) -> bool}`; PKG-400, 401. Why: the 20 per hour limit and level A/B triggers have no wire format.
- ilium-plugin-host `registry_client::TransferStatement` and `verify_transfer(&TransferStatement, &TrustStore) -> Result<(), Diagnostic>`; PKG-390. Why: the statement format is not in the manual; only `transferred_from` display is tested.
- Unspecified wire formats (manual gap, not skeleton): the `[plugins.registry]` keys `urls`, `root`, `offline`, `allow_insecure_localhost`, `proxy` (shape of `urls`/`root` assumed as arrays of strings); the `search --sort name|updated|relevance` flag (PKG-382 names the orders but no flag); the `publish --category` flag (PKG-384 names the refusal but no input); the `dependencies` member of a version object in `plugins/<id>.json` (assumed id to range map, PKG-440); the server answer when a publish is refused (PKG-393); the YANK and DEPRECATE request shape (PKG-396, 397); the `ilium-plugins.lock` form `install --locked <file>` versus `plugins.lock` (PKG-359 and PKG-428 differ).
- Spec conflicts the tests avoid: PKG-371 (https only) against PKG-438 (`registry add` http gives `usage.invalid-value`) is tested by writing http URLs into the configuration directly; PKG-409 (partial mirror re-signs) against PKG-439 (no signed byte changes) is tested only for full copies; `trust.key-permissions` (signing page PKG-212) against `sign.key-permissions` (CLI page DEV-116) is left to the keys lane.
- Partly untestable rows: PKG-391 (disputes) is doc_ only; PKG-386 (DNS TXT claim), PKG-402 (content policy), PKG-404 (appeal), PKG-401 (review levels), PKG-385 (id forms), PKG-372, 374, 375 resume and PKG-373 timeouts are doc_ tests; PKG-377 `default` marker is not tested; PKG-390 transfer is tested only for the displayed `transferred_from`.
