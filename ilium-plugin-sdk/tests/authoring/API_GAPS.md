# API gaps found by the authoring lane (part 1)

- ilium-plugin-sdk, Cargo.toml: `[dev-dependencies] ilium-plugin-sdk = { path = ".", features = ["testing"] }` (or `[[test]] name = "authoring" required-features = ["testing"]` plus running with `--features testing`). Every test imports `ilium_plugin_sdk::testing`. Requirement: all AUT ids.
- ilium-plugin-sdk (facade over sdk-core), free functions as the cookbook writes them: `pub mod host { pub mod timers { pub fn set(after_millis: u32, repeat_millis: Option<u32>) -> Result<TimerId, PluginError>; pub fn cancel(timer: TimerId); } pub mod clock { pub fn now_unix_millis() -> u64; pub fn monotonic_millis() -> u64; } pub mod storage { pub fn get(bucket: Bucket, key: &str) -> Option<Vec<u8>>; pub fn put(bucket: Bucket, key: &str, value: &[u8]) -> Result<(), PluginError>; pub fn remove(bucket: Bucket, key: &str); pub fn lease(key: &str, ttl_millis: u32) -> bool; } } `. The skeleton exposes only the `Host*` traits and an empty `HostCalls`. AUT-002, AUT-003, AUT-004, AUT-007, AUT-009, AUT-010, AUT-018, AUT-025. The tests use local doubles of the recipes until these exist.
- ilium-plugin-sdk-core: `HostCalls`/`HostApi` need the timer, clock, storage and journal methods so that a plugin written for `NativeEntry` can call the host inside the FakeHost (same ids as above); `host()` and `set_host()` are unimplemented stubs.
- ilium-plugin-sdk-core, `NativeEntry`: no render or action dispatch (`fn native_render(&mut self, target: ViewTarget, columns: u16, rows: u16) -> UiTree`, `fn native_on_action(&mut self, action: UiAction)`), so `FakeHost::render`, `click` and `send_action` cannot drive a plugin view. Needed for the view rules AUT-407, AUT-501, AUT-502, AUT-503, AUT-504, AUT-505, AUT-506 (rendered-view tests at 40 by 12, compact density, both icon modes, reduced motion).
- ilium-plugin-testkit, FakeHost: the cookbook test `host.deliver(vec![text_changed()])` followed by `host.advance_clock(300)` expects `advance_clock` to fire due timers into the plugin (AUT-002, AUT-003); `breach_deadline` is called with the export name `"on-events"` (assumed spelling, AUT-022).
- ilium-plugin-testkit, FakeHost: `inject_trap("trap.panic")` is expected to record one failure with that code and schedule one restart of 1000 ms (DEV-490), used by AUT-018.
- CLI lane (not this crate): AUT-302 to AUT-309, AUT-318, AUT-320 and AUT-401 to AUT-403 name `ilium plugin check`, `lint`, `pack`, `sign` and `verify` outcomes; this lane only checks the pages and the lint tables (`docs_consistency.rs`).
- Part 2 (AUT-507..804): doc-lint tests only (assert_rule); no new gaps. AUT-613 fake-clock formatting behaviour needs the clock calls listed above to be testable beyond the page rule.
- Part 3 (AUT-623..955, release and registry rules): `ilium-plugin-host::i18n::host_text_for_language_tag` (AUT-624, a tag outside English, German and French shows English for every host text) is not in the host crate. `ilium-plugin-testkit::i18n::pseudo_locale_check` (AUT-625, the `en-XA` pass over every host dialog and core plugin view, with an `i18n.layout-overflow` finding blocking release) does not exist. `ilium-plugin-testkit::conformance::run_suite` (AUT-950) has its signature but its body is `unimplemented!("conformance.suite")`, so the zero-fail-verdict test cannot run yet. AUT-623, 951 to 955 are doc-lint tests of the guide and the requirement table.
